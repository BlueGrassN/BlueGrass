# 四端 Xray 与品牌更新实施计划

用户已授权直接更新根目录 logo，将所有客户端内核统一到 Xray，并写入四端开发手册。

2026-10-19 范围调整：用户明确要求本会话只完成 Windows 相关设置，Android 由另一会话继续。此前的 Android 源码/素材迁移改动保留为未完成的交接状态，不继续修改、构建或宣称验收。四端唯一核心原则及已有手册继续保留；本次最终产物只验收 Windows。

1. 固定官方 Xray-core 版本与提交，检查真实源码中的协议、TUN 和平台接口；不把改名或包装旧内核当作迁移。
2. 更新共享 `core/protocolconfig`：保留结构化资源校验，生成 Xray 出站配置，并提供受会话生命周期约束的 TCP/UDP 拨号。Windows 本地 HTTP 网关继续监听 `127.0.0.1:12808`。
3. 迁移 Windows TUN 与 Android VpnService 接入，保留暂停、连接清理、网络绑定、DNS、出口观测与平台授权边界。去除 sing-box 运行依赖；必要的独立 TUN/网络工具库不作为另一套代理内核。
4. 接入根目录提交的新品牌资源，覆盖已实现客户端的页面标志和系统图标，并保留浅色/深色可读性。
5. 更新许可、依赖锁、构建脚本、协议能力说明、四端共享开发手册和各平台入口。iOS/macOS 若无实现，仅记录真实状态及必须遵守的 Xray 接入契约，不伪造可运行产物。
6. 运行对应 Go、Flutter、原生桥接与打包检查，检查发布产物不含旧内核；Windows 每次打包后安全替换 dist 解压目录，外层保留主程序和 runtime 文件夹。

并行写入范围：主任务负责共享协议/Windows HTTP 网关/依赖与发布集成；独立任务分别负责 Windows TUN、Android 原生桥接、品牌资源和开发文档。集成时检查接口及依赖一致性。测试账号与本机会话不进入源码快照、日志或发布包；不修改用户的 10808 代理服务。
