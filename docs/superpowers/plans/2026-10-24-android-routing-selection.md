# Android 分流选择实施计划

**Goal:** 安卓提供与 Windows 相同的“国内外分流 / 全局代理”，设置持久化，实际 DNS/TCP/UDP 路由生效，并在 Android Studio 模拟器验收。

**Architecture:** 复用 `core/routingpolicy` 的固定版本 GeoSite/GeoIP 数据与分类逻辑。Flutter 负责选择和状态，Kotlin 保存偏好并将模式纳入原生会话身份，Go 负责 DNS 和 TCP/UDP 去向。使用当前已授权工作区继续开发，保留已有未提交实现。

**Tech Stack:** Flutter/Dart、Kotlin VpnService、Go/Xray、Android 11 模拟器。

## 已确定的设计

- 标签沿用 Windows：“国内外分流”“全局代理”。国内域名优先直连，已知国外域名优先代理，未知域名按公网 IPv4 归属判定。域名分类与 DNS 选路必须保持一致，不能仅添加 UI 开关。
- 新安装默认 `bypass_cn`；已有安装没有该字段时迁移为 `global`，保持此前行为。读取模式先于生成新设备 ID；迁移依据已有持久化设备记录，成功写入后才确认设置。
- 模式仅允许在 VPN 空闲且无连接/存储操作时切换；连接、暂停和恢复期间显示实际会话模式。改动期间禁止发起连接，存储失败显示错误且保持原模式。
- 原生 JSON 增加可选 `routingMode`；旧调用缺省为 `global`，显式非法值拒绝。资格刷新、界面重建和切网不会改变活动模式。分流模式及规则加载失败不得退化成任意直连。
- 复用受保护且绑定底层 Network 的直连套接字；保留到期、暂停、退出清理、局域网与公网 IPv6 阻断语义。出口检测继续显示所选节点出口。
- 测试使用既有指定账号，仅运行时读取凭据，不写入代码、APK、截图或日志；不变更生产节点。

## 实施与验收

- [x] Go：配置校验、共享规则、域名/DNS 路由、TCP/UDP 字面 IP 与域名分类；测试国内域名海外 IP、国外域名国内 IP、未知 IP、无直连回退及暂停失效。最终包含 TTL 缓存、并发刷新与多地址应用回退，325 个测试/子测试通过。
- [x] Kotlin：持久化默认/迁移/失败、配置与快照模式、资格刷新身份；对应设备/状态机测试。
- [x] Flutter：首页及设置入口、保存与交互锁定、连接/刷新/恢复模式传递；对应控件与控制器测试。116 项通过。
- [x] 整体复核与必要回归：Flutter analyze/test、Go race/vet、Android instrumentation。设备 70 项通过，独立复核无剩余问题。
- [x] 重建双 ABI AAR 与正常 APK，在模拟器真实 UI 切换两模式：国外 HTTPS/UDP 均经节点，国内目标全局经节点而分流直连；验证保存恢复与连接中禁止切换。最终两模式所有必测项通过，脚本退出码 0。
- [x] 更新版本、依赖信息、验收文档并交付 APK。0.3.0+4 已安装，最终 AAR 依赖已校验，临时探针清理，应用断开 VPN。

完整结果：[分流模式验收](../../../Android/docs/routing-verification-20261024.md)。国内域名 HTTPS 使用相同 DNS 的独立直连基线比较，固定 IP HTTPS 的一次瞬时失败及复测通过均保留证据。

## 复核重点

- DNS 域名与真实目标 IP 不一致时仍遵循域名优先级；不能按共享 IP 缓存误授权其他域名直连。
- 旧/未知 FakeIP 不得映射到其他会话的新域名；解析私网/IPv6不能借分流获得公网直连许可。
- 偏好写入失败或连接竞态不得使显示模式与实际核心模式不一致。
- 网络恢复与资格刷新维持原模式；模式变化不能被当成单纯续期。
- 真实国内外探针必须独立于被 VPN 排除的 BlueGrass UID，以观察实际 TUN 转发。
