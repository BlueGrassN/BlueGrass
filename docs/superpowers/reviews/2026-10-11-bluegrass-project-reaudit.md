## 2. 后端新增发现

以下 P2 表示应在生产交付或相应功能验收前处理；“确定”指能从当前代码确认的缺口，不代表已经在运行环境复现。备份恢复语义单列为待定契约。

### A01 · P2 · 初始化检查不能证明会话数据库完整

证据：[main.go:183](../../../client-api/cmd/client-api/main.go#L183) 只检查 `sessions.id`；[store.go:41](../../../client-api/internal/session/store.go#L41) 依次使用 `CREATE TABLE IF NOT EXISTS` 创建三张表，已有表不会因此校验或修复。

若第一次迁移建好 `sessions` 后中断，或者备份恢复遗漏 `refresh_tokens` / `device_sessions`，现有 `-check` 和启动流程仍可能通过，随后登录/续期才报错。完整列、关键索引、外键和 InnoDB 条件也没有结构检查。

最小补全：独立会话 schema 版本/完整性检查；部分迁移、缺表、缺列和错误引擎的失败用例。只检查自身表，不自动修改共享业务表。

### A02 · P2 · 启动依赖故障后的恢复机制不完整

证据：[main.go:172](../../../client-api/cmd/client-api/main.go#L172) 在启动时数据库不可用就退出；[服务单元](../../../client-api/deploy/bluegrass-client-api.service#L4) 限制 60 秒内最多启动 5 次，失败后每隔 3 秒重启。

推导场景：启动或重启期间数据库连续快速拒绝连接，会耗尽启动额度；数据库随后恢复，并不构成重新启动该服务的触发器。systemd 官方说明达到启动限制后不再自动尝试重启，需要后续人工、定时器或其他启动触发。[官方手册源码](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.unit.xml)

最小补全：明确依赖故障时的持续退避或再次启动机制、告警及人工恢复步骤；验证数据库晚于 API 就绪、数据库短暂中断和服务重启组合。本轮没有在 Hytron 做故障演练，也没有断言线上当前停机。

### A03 · P2 · 读取限流没有覆盖鉴权数据库查询

证据：[httpapi.go:96](../../../client-api/internal/httpapi/httpapi.go#L96) 的顺序为 `protected(read(...))`；[handlers.go:48](../../../client-api/internal/httpapi/handlers.go#L48) 先调用鉴权，第 67 行才按会话限流；[service.go:237](../../../client-api/internal/auth/service.go#L237) 查询会话，随后核实业务账号。

因此，同会话超出读取配额后的请求仍会访问鉴权数据库；格式为 `bga_` 加 64 个字符的无效令牌也会进入会话查询，而没有登录/续期那样的鉴权前 IP 限频。已有在途上限和连接池限制并发数，但不能把持续请求率限制为每分钟 120 次。

最小补全：在受保护请求鉴权前增加有界入口预算，并保留鉴权后的会话配额；用无效令牌、超额有效令牌及正常请求混合测试数据库调用数和恢复能力。这是抗滥用及负载缺口，不是鉴权绕过。

### A04 · P2 · 清理工作量和设备记录生命周期没有闭环

证据：[store.go:284](../../../client-api/internal/session/store.go#L284) 的 `Prune` 分别更新/删除至多 1000 条记录，并在最后删除父会话；[第 56 行](../../../client-api/internal/session/store.go#L56) 的刷新令牌外键级联删除，[第 62 行](../../../client-api/internal/session/store.go#L62) 的设备外键只置空。

三个具体缺口：

1. `LIMIT 1000` 限制各语句显式选择的行数，不限制整批总工作量；一个父会话即可级联删除大量刷新记录。整个流程在一个事务内，末尾超时会回滚之前的清理。
2. `device_sessions` 没有清理分支；历史设备在会话删除后永久保留空关联行，随重装/换设备增长。
3. [运行记录:44](../../../client-api/docs/OPERATIONS.md#L44) 明确没有安装清理定时任务。一次命令只有一批，没有清理数量、剩余积压或追赶完成标准。

最小补全：为子记录和空设备记录确定保留策略，按实际数据库工作量分批，提供清理计数与积压监测，落实调度；验证大刷新链、并发续期、超时回滚与重复执行。不能直接随意删除仍参与登录串行化的设备锁行。

### A05 · P2 · 超过 180 天的重放撤销行为与契约不一致

证据：[API.md:25](../../../client-api/docs/API.md#L25) 承诺不同 `request_id` 重用旧令牌会撤销设备；[store.go:289](../../../client-api/internal/session/store.go#L289) 会删除消费超过 180 天的令牌，未限定其所属会话已经结束；[service.go:210](../../../client-api/internal/auth/service.go#L210) 在记录消失后只能返回 `invalid_refresh_token`。

场景：会话持续续期超过 180 天，清理早期已消费令牌后，再重放它不会进入 `refresh_reuse_detected` 的整会话撤销分支。当前滑动会话没有固定总寿命，不能用“会话早已过期”解释该差异。旧令牌仍被拒绝；问题是丢失检测和撤销能力，不是旧令牌能直接获得权限。

最小补全：明确重放检测保留边界并与长期会话契约一致，决定保留活动会话的历史摘要或采用等效机制；新增“跨 180 天持续续期 → 清理 → 旧令牌重放”的组合测试。[一年以上会话测试](../../../client-api/internal/auth/service_test.go#L86) 当前没有调用 `Prune`。

### A06 · P2 · 会话数据库恢复缺少防止旧授权重新生效的流程

证据：[store.go:259](../../../client-api/internal/session/store.go#L259)、[第 267 行](../../../client-api/internal/session/store.go#L267) 和 [第 280 行](../../../client-api/internal/session/store.go#L280) 将轮换、消费和撤销状态全部持久化于会话库；[README:48](../../../client-api/README.md#L48) 只要求保留配置、密钥及会话库。

待验证场景：恢复撤销/轮换前的数据库备份并沿用原密钥，账号密码未变、备份中的会话还未到期时，旧令牌可能重新通过校验。这是数据库回滚恢复与正常代码升级不同的授权风险；当前没有现场备份流程证据。

最小补全：明确恢复后统一失效或保留撤销历史的措施、密钥与数据库的恢复顺序，做隔离备份恢复演练。是否支持平滑密钥轮换另行决定，不能擅自把它作为已接受需求。

### A08 · P2 · 关键边界测试和强制集成验证入口缺失

仓库有 91 个顶层测试函数，但 [testdb.go:27](../../../client-api/internal/testdb/testdb.go#L27) 在未设置 `GO_API_TEST_CONFIG` 时会跳过真实 MySQL 测试；此行为在 README 已明确说明。本轮文件清单没有 CI 工作流或强制要求这些测试实际执行的验证入口。

现有 [会话测试](../../../client-api/internal/session/store_test.go#L42) 覆盖同请求并发、重放、设备锁和锁超时，仍缺 `Prune`、旧代次 `stale_refresh`、恢复窗口 `refresh_retry_expired`、收据篡改/错误密钥、部分迁移和备份恢复的针对性回归。最新中转规则选择有 SQL 结构检查，但真实 MySQL fixtures 还应覆盖多条 active 规则及失效最新规则。

最小补全：补这些行为测试，为独立 MySQL 测试环境提供可重复入口，验证任务在必需集成测试被跳过时失败；留存 revision、环境、实际执行/跳过数和结果。历史的 91 个测试通过不能自动覆盖这些新发现。

### C09 · P2 · 凭据日志规则和少量现行文字仍有冲突

[接入文档:167](../../development/client-api-integration.md#L167) 禁止把节点用户名和密码写入日志或诊断摘要；[补充设计:755](../specs/2026-10-10-sunipip-client-design-addendum.md#L755) 却保留中转用户名首尾各两位。短用户名可能被这一规则完整保留。应统一诊断数据白名单，用非秘密关联标识排障，并补短用户名、嵌套错误对象和分享链接的假秘密测试。这是文档规则冲突，尚无客户端日志泄漏的运行证据。

[D-18:30](../../adr/0018-bluegrass-branding.md#L30) 仍写首版网页取数，应注明接入路径已由 D-19 替代；其品牌决定不变。RC/GA 门禁不一致已并入 C08。已明确标为历史的 PHP 方案和原审阅建议，不逐条当作现行冲突重报。
