### F01：账号门槛没有贯通刷新、判定与已有连接处置

证据：D-05:42 要求连接前取得账号资格和资源；A:589 只列刷新资源。A:286 有账号受限判定，但 A:307–314 的已有连接处理表没有对应事件。M:144–151 也缺账号受限行及完整判定表引用，R:201、206 的同步说明不足以证明已补齐。

触发场景是账号限制改变、旧账号快照下点击连接，或后台刷新明确返回限制。当前文字无法确定哪些限制暂停已有会话、哪些只要求补验证。应依据 B-07 的真实含义补刷新范围与事件动作，并把主设计同步到同一套规则。网络失败和未知状态仍遵守已有会话规则，不擅自变成失联封禁。

### F02：两处中转规则并存时没有确定结果

证据：M:120 接受顶层和订阅内两处 `forward_rule`；A:240 只处理命名风格冲突，A:319 要求测试两处并存却未写预期。

当一处为 active、另一处为 disabled，或入口/关联不同，直接从不同位置拼字段会产生不同资格结果。S1/B-03 需明确权威来源、整组关联与冲突处理，再形成共享向量；不能仅用两个字段是否非空来推断。

### F03：运行期有效期更新和自动暂停缺少原生消息契约

证据：A:109、309、573 要求更新原生到期调度，A:153、172、469 要求自动暂停；A:417 的方法表未定义对应操作或复用方法的语义。A:98 只有请求幂等标识，尚未明确持续会话标识与更新代次。

续费、缩短有效期或撤销时，不能由实现者自行选择重新 Connect 或 Disconnect。应明确消息映射、会话匹配、应答、幂等及失败动作，覆盖界面重连 IPC、原生服务恢复和迟到结果。可以新增方法，也可以完整定义现有方法的承载方式；关键是暂停不得误走解除保护路径。

### F04：同会话刷新乱序及旧 401 的处理没有边界

证据：A:309 只要求资源/会话匹配，而 A:588–592 有多个刷新触发源。同一会话的旧成功结果仍可在撤销或续费结果之后到达。A:137 的“任意请求返回 401”和 A:607 的清令牌规则也没有绑定发出请求时的登录代次。

需要明确串行刷新或版本/代次裁决，并让账号、数据源与登录代次随请求传递。验收至少覆盖：撤销后旧有效结果到达、续费后旧到期时间到达、切换账号或重登成功后旧 401 到达。旧结果不能重开业务或清掉新令牌；不能用“取最大有效期”代替排序规则。

### F05：Android 局域网排除与业务 DNS 接管冲突

证据：M:249 禁止局域网豁免放行业务 DNS，A:387 要求接管目标端口 53；A:498 却将局域网用 `excludeRoute` 或补集路由排除。官方接口接受 IP 前缀，按目标路由匹配，没有端口条件。[Android VpnService.Builder 官方接口](https://developer.android.com/reference/android/net/VpnService.Builder#excludeRoute(android.net.IpPrefix))

由这些规则推导：允许局域网且未启用系统 lockdown 时，普通应用直接查询路由器 TCP/UDP 53 的流量可能绕过内核。仅设置 VPN DNS 不能证明显式发往路由器的查询已被接管。应设计能区分 DNS 与允许的 LAN 流量的路径，例如让 LAN 先进入 VPN 再由内核分流，并由 S7/S9 验证 API 33 前后和 TCP/UDP 两种查询。这里记录的是方案冲突，尚无实际抓包结论。

### F06：控制面能走 HTTPS，但冷缓存解析路径缺失

证据：A:361、370 要求代理故障时控制面仍直连；A:444–445 只写服务的入口 DNS 与界面 TCP 443 放行；D-04:18–20 将现有 DNS 策略限定在中转入口。

当保护已阻断、中转不可达、登录/更新域名又没有可用 DNS 缓存时，现有设计不能说明如何得到目标 IP。应补“受信域名—解析执行方—上游—物理网络绑定—过滤规则—HTTPS 原域名验证”的完整契约，并定义服务接口和缓存失效。验收必须冷缓存开始，不能用缓存命中掩盖缺口，也不能整体放开普通应用 DNS。

### F07：网络修复和卸载使用了更弱的代理归属判断

证据：A:466 保存代理开关、服务器、例外、PAC 与自动检测快照；A:470 要求当前设置仍等于本产品写入值才恢复。A:461 的修复工具只检查端口，A:724 的卸载也只有“仍指向本产品”的粗略条件。

若其他软件保留端口但修改 PAC、例外或开关，修复可能覆盖后来设置。界面、修复工具和卸载器应共用明确的归属判定、无快照策略及目标用户识别。用“端口相同、其他字段已变化”的用例验证，不把端口匹配当作全部字段的所有权证明。

### F08：时间跳变和跨重启恢复规则不完整

证据：A:571 使用本机时间加偏移，A:217 的会话持久化字段未明确时间锚点；D-15:26–29 要求原生与界面一致、不能延长已知权益。A:580 对无时区时间暂按 UTC+8，真实语义仍待 B-03。

需要定义校时后系统时间改变、休眠唤醒、离线重启和原生进程恢复时采用什么时间依据、何时重算。P:387 又允许 `validUntil` 后 60 秒内暂停，而 D-15:20 与 A:172 写到期停止：应明确这 60 秒是观察/界面容差还是转发容差，不能在验收时自行解释为额外授权。新增连接/验证放行不得越过已知有效期；最终授权仍由服务端执行。

### F09：有效签名旧配置与旧清单没有接受规则

证据：A:687–688 有结构版本、签名和回退缓存，A:702–703 有发行版本与签名选择流程，但没有说明已接受较新内容后如何处理镜像返回旧的有效签名内容。

签名有效不能单独回答新旧顺序。应规定配置和清单各自的版本/序号、已接受状态、同版本异内容、镜像倒退以及允许的恢复操作。旧配置可能降低最低版本或恢复过时端点；当前没有唯一的预期结果。此处治理发布元数据，不改变 D-15 的业务缓存期限。

### F10：强制更新与灰度的优先级不明确

证据：A:696 低于最低版本就禁止新连接；A:702 有“是否强制”，A:703 仍先按安装 ID 判断灰度。

当前版本已被禁用、但唯一兼容更新包未命中灰度时，用户可能需要更新却取不到候选包。应写明最低版本、强制标志、灰度、通道和无兼容包的决策表及发布端约束。现有哈希选取算法已覆盖，不重复设计算法；不能擅自决定永久跳过灰度或解除最低版本门槛。

### F11：签名格式和密钥轮换还停留在原则

证据：A:688 写“规范化 JSON”和两把内置公钥，A:707–715 规定保管方式；尚未定义签名字节、签名字段封装、key ID、轮换顺序、旧钥退役和信任恢复。Windows 发布者及 Android 签名“身份一致”也缺允许身份与变更规则。

应形成可供发布脚本、Dart 和原生层共同使用的格式及正反测试向量，补正常换钥、旧版本升级、退役旧钥及错误身份的处理流程。保管私钥与双方能正确验签是不同交付物。具体方案由 P0-04/REL-04～REL-07 锁定。

### F12：维护升级尚未成为可恢复的独立事务

证据：D-13:19–20、A:704、723 要求维护暂停并保留保护；A:176 的正常退出则执行完整停止，A:417 未定义维护交接。

需要明确安装器/UI/服务的维护命令与确认点、写入的阶段状态、停止/替换/重启的顺序，以及每阶段中断后的恢复和版本不兼容处置。关闭 UI 进行升级不能被误当成用户主动退出；替换失败也不能直接进入删除规则的卸载流程。按阶段注入故障才能关闭该项，单次成功覆盖安装不够。

### F13：零泄漏验收没有限定适用模式

证据：A:356–358 明确 Windows 系统代理模式中其他程序、UDP 和部分系统 DNS 可直连；P:393–394 却未限定模式地要求无业务 DNS 和零直连。

应把系统代理、TUN/VPN、保护阻断及合法控制例外写入验收矩阵。系统代理验证受代理控制的流量与限制提示；TUN/VPN 验证其保护范围内禁止流量零泄漏。避免把已接受的系统代理能力判成失败，也避免测试者临时扩大白名单放过实际泄漏。

## 5. 建议处理顺序与门禁

1. **在相关实现开始前补齐契约**：F01～F06 的账号/字段、异步状态、IPC 与 DNS 路径；F08 的时间依据与到期动作。这些直接决定领域层、原生层和测试的预期结果。
2. **同步修正文档与验收**：F07、F13、F14，以及 G-19/G-29 的交互与无障碍成果。P:338 的测试工具注释统一到 Q-02 的多协议范围。
3. **在发布工程实现前定稿**：F09～F12 的配置/清单新旧判定、强制更新优先级、签名格式/换钥与维护事务；G-28 的停发/放量流程。
4. **推进已授权范围内的 Phase 0 准备与原型**：按 S1～S12 收集书面结论和证据。需要真实样本或外部服务的条目标记具体依赖，其余独立工作可以继续；不能用“ADR 已接受”代替验证结果。

现有门禁还需统一两处表述：P:19 的 M1 要求“P0 级后端依赖有书面答复”，P:98 又明确 B-01 未确认时继续其他工作；应明示例外如何记录、M1 是否带条件通过及后续阻断点。R:160/P:420 写 GA 前落实 B-01，而 P:23/P:412 更严格地要求 RC 前落实；核对期间按更明确的 RC 门禁跟踪，不把这一差异解释为已获准跳过验证。

日期与工作量继续按 P:10–11 标注为原基线。P:20 的 Alpha 日期仍以确定值显示，后续排期修订应统一为待重估状态。当前没有足够证据确认原 354 人日或里程碑日期仍可兑现。
