# 统一开发预览版 Release

用户选择：固定一个 Release，集中各端最新安装包。

- 固定 tag `preview`、标题 `BlueGrass 开发预览版`，页面集中 Windows x64、Android ARM64、macOS arm64/x86_64 下载。
- 各端保留现有版本号、构建号、签名方式和构建验证。iOS/HarmonyOS 尚无安装包，不伪造下载。
- 独立构建流程只上传 artifact；统一发布器在主分支构建完成后，重新检查全部平台最新成功运行。PR、非 main 和其他仓库运行不得进入发布。
- 单一并发组串行更新。即使待运行任务被合并，后一个发布器仍会检查所有端。失败的端保留已发布版本；成功的其他端可更新。
- 安装包及配套元数据使用平台、版本/构建号、attempt 命名，校验 SHA256 与源码/构建身份，先上传完整新附件，再一次更新页面及隐藏状态，最后清理本发布器管理的旧附件。重跑幂等，旧构建不回退新版本。
- `preview` 是下载集合入口，不代表三端来自同一源码版本。页面逐端记录实际 commit、运行链接；tag 不强制移动，源代码自动压缩包不能代表全部安装包源码。
- 历史平台 Release/tag 保留，停止新增平台 tag；现有成功 artifact 用于首次汇总。

## 方案比较

用户选择固定滚动入口；每个统一版本另建 Release 会要求独立版本同步，不符合本次选择。三个工作流直接改同一 Release 容易互相覆盖说明和校验文件，因此使用统一发布器。

## 验收

离线测试覆盖哈希/身份拒绝、PR 隔离、旧运行晚完成、单端失败保留、多端合并和发布失败恢复；工作流静态检查通过；真实 GitHub `preview` 页面能同时下载四个安装包且附件摘要匹配。
