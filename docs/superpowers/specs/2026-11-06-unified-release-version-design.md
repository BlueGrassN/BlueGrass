# 统一预览版版本与清理

用户明确要求仅保留 preview 的发行产物，并确认全端以 Windows 的基础版本 `0.1.0` 为起点：页面、文件名和应用显示均使用 `X.X.X`，系统内部构建号继续递增，以后只修改一个公共版本配置。README 仍只在本地维护。

根 `release.json` 是公开应用版本的唯一来源；Windows/Android/macOS 构建均读取并注入版本，平台内部 build/versionCode 维持原有递增规则。公共界面显示纯版本；历史诊断元数据不伪造。所有可交付平台都必须重新构建，不能只改旧包标签。

下载文件采用 `BlueGrass-平台-X.X.X-架构` 命名，不附加 beta、dev、+build 或 attempt。为保持上传验证后再切换页面的安全顺序，一个已发布版本的文件内容不可覆盖；同版本重跑保持现有发布，下一次发行修改公共版本号，例如 `0.1.1`。新版本等三个平台（Mac 含双架构）全部准备就绪后整体发布，任一未完成或失败时保持上一组下载。

保留可信 main、提交归属、签名、哈希、版本/运行防回退、上传与清理恢复保护。旧 schema 状态可读取，迁移完成前保留真实旧版本；新版本整组验证后清理旧 preview 附件。用户授权删除非 preview Release 及附件，Git 源码标签不在清理范围。

选择公共版本配置与整组切换，避免仅修改页面造成安装包实际版本不符，也避免同版本稳定文件名覆盖破坏旧下载。真实设备联网和正式签名/公证状态沿用原验证边界。

上传前记录隐藏 pendingRelease 所有权清单，保留旧页面与草稿状态；中断后核验并清理仅本次未发布附件，再恢复选择与发布，避免同版本较新构建造成永久同名冲突。已发布附件仍通过 retiredAssets 清理恢复。
