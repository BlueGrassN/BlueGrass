## 2. HTTP 约定与接口清单

以下路径均相对于上述基址。发送 JSON 时使用 `Content-Type: application/json`，接收 JSON 使用 `Accept: application/json`。受保护请求只能通过 `Authorization: Bearer <access_token>` 传令牌；不得放入 URL、日志、崩溃报告或普通偏好设置。

| 方法 | 路径 | 认证 | 输入与结果 |
| --- | --- | --- | --- |
| POST | `/auth/login` | 无 | 用户名或手机号、密码、设备标识；返回令牌对与客户摘要 |
| POST | `/auth/refresh` | 刷新令牌在 JSON 中 | `refresh_token`、`request_id`；返回轮换后的令牌对 |
| GET | `/me` | Bearer | 返回 `id`、`username`、`display_name` |
| POST | `/auth/logout` | Bearer | 撤销当前设备会话，成功的 `data` 为 `{}` |
| GET | `/nodes` | Bearer | `per_page`、可选 `cursor`；返回本人当前可连接节点页 |
| GET | `/nodes/{subscriptionId}` | Bearer | 重新核实本人指定订阅并返回当前节点配置 |
| GET | `/health` | 无 | `data` 为 `{"status":"ok"}`；仅存活检查，不证明数据库就绪 |

成功响应统一为 `success: true`、`data`、`server_time`；失败响应为 `success: false`、`error: {code, message}`、`server_time`。时间使用 UTC RFC 3339 格式。按 HTTP 状态及 `error.code` 分类，不能依赖 `message` 文案；当前错误消息为通用 HTTP 状态文本。响应禁止缓存。

请求体最多 4096 字节，只接受合法 UTF-8 JSON 对象，拒绝未知字段和尾随 JSON。`username` 最多 255 字节且不能为空或含控制字符，`password` 为 1–1024 字节；`device_id` 和 `request_id` 使用非零标准 UUID。可选 `device_name` 最多 120 个 Unicode 字符且不超过 480 字节，不含控制字符。

## 3. 登录与长期会话

**短信接入方向已确定、接口未实现**：[D-26](../adr/0026-reuse-existing-sms-provider.md) 采用官网现有短信供应商、签名和模板，由独立 Go API 发码、校验并签发本客户端会话；不复用官网登录令牌或验证码消费链路。具体配置、模板变量、发送/校验端点、验证码期限及限频规则仍需核实。下述已实现的登录示例仍为密码登录。

[D-27](../adr/0027-sms-limits-without-captcha.md) 确认不接入图形/滑块或验证网页；独立 API 执行发送频率、发送数量及验证码错误次数限制，达到限额时拒绝并提供适用的等待信息。客户端倒计时不替代服务端限制。用户已于 2026-10-11 将参数来源与具体数值的讨论延后；验证码有效期、重发/消费及限额仍待定稿，不默认沿用官网或采用自定数值。

### 3.1 密码登录

以下均为虚构示例，令牌和密码占位符不可用于实际请求：

```json
{
  "username": "demo-user",
  "password": "EXAMPLE_PASSWORD",
  "device_id": "cce6c5b7-4448-4351-9d80-3a73ef6369b4",
  "device_name": "BlueGrass Windows"
}
```

`POST /auth/login` 成功示例：

```json
{
  "success": true,
  "data": {
    "token_type": "Bearer",
    "access_token": "EXAMPLE_ACCESS_TOKEN",
    "expires_in": 1800,
    "access_expires_at": "2026-10-11T08:30:00Z",
    "refresh_token": "EXAMPLE_REFRESH_TOKEN",
    "refresh_expires_at": "2027-04-09T08:00:00Z",
    "session_id": "EXAMPLE_SESSION_ID",
    "customer": {
      "id": 123,
      "username": "demo-user",
      "display_name": "Demo"
    }
  },
  "server_time": "2026-10-11T08:00:00Z"
}
```

默认访问令牌有效期 30 分钟，刷新令牌的闲置有效期 180 天；成功续期后重新计算闲置期限，没有固定的会话总寿命。持续使用可以长期自动续期，不需要每 30 分钟重新输入密码；长期未使用或会话失效时仍需按接口错误处理。

每次安装生成并持久化一个 `device_id`，不能每次启动或每个 HTTP 请求生成新的设备 ID。同一账号、同一设备重新登录会撤销该设备的旧会话，其他设备独立；官网的登录令牌与此处会话独立。手机号登录使用目录索引，刚变更的手机号可能等待默认 30 秒的目录刷新；仍可使用用户名登录。

客户端无需上报 IP。2026-10-12 本地 API 增加成功登录来源记录，服务端将连接／可信代理识别的 IPv4 或 IPv6 写入会话表 `login_ip`，结合 `customer_id` 和 UTC `created_at` 查询。登录 JSON 和返回字段不变，不接受 `login_ip` / `client_ip` 参数；续期不覆盖初始登录 IP，也不按 IP 绑定会话。已有表需先补列再部署新程序，见[部署手册](../../client-api/docs/DEPLOYMENT.md)第 5.3 节；同日 Hytron 测试库已补列，但 API 程序尚未更新，不能视作实际登录 IP 写入已经启用。

### 3.2 自动续期、并发与异常恢复

```json
{
  "refresh_token": "EXAMPLE_REFRESH_TOKEN",
  "request_id": "d0d57b8b-0358-4fc5-a3ea-b8975eeb963b"
}
```

`POST /auth/refresh` 不需要访问令牌，成功返回与登录相同的字段。令牌视为不透明字符串，不解析或猜测其格式。

客户端实现一个会话管理器，同一设备会话的所有请求共享它：

1. 可在访问令牌即将过期时主动续期；受保护请求收到 `access_token_expired` 或 `invalid_token` 时，等待同一轮续期，再将原请求重试一次。多个请求同时失败只能触发一次续期。
2. 发起续期前，在安全存储中保存待恢复记录：当前 `session_id`、本轮原始刷新令牌及新生成的 `request_id`。进程重启也必须能恢复这条记录。
3. 断网、超时、429 或 503 后，用**相同刷新令牌和相同 request_id**重试，遵守 `Retry-After`，加入退避和抖动。不得换一个 UUID 重试同一旧令牌。默认 120 秒恢复窗口内，相同请求可取回相同结果。
4. 成功后原子保存新令牌对和到期时间，再清除待恢复记录；迟到响应不能覆盖已保存的更新一代令牌。原子性可以通过单个加密会话记录或带版本的持久化实现。
5. `409 stale_refresh` 表示会话已经发生后续续期：重读安全存储并使用更新令牌；若无法恢复更新令牌则重新登录。`409 refresh_retry_expired` 表示取回旧结果的窗口已过：已保存新令牌则继续使用，否则重新登录。
6. 用不同 `request_id` 重用已消费的刷新令牌会触发 `refresh_reuse_detected` 并撤销该设备会话。不能让节点列表、详情、前台恢复分别持有独立的刷新逻辑。

120 秒是服务端的恢复窗口，不是保证网络失败后总能恢复。若 `Retry-After` 超过剩余窗口，不得绕过限流；按上述已保存状态恢复或重新登录。普通节点同步的分钟级退避不得原样套用到令牌结果恢复。

### 3.3 平台归属与登出

Windows 由当前用户的界面进程持有账号会话，使用 DPAPI 当前用户作用域；Android 使用 Keystore 保护的加密存储。保存令牌、设备 ID、会话 ID 和待恢复记录，不保存登录密码。缓存命名空间包括服务环境、数据源版本与账号 ID。

Windows LocalSystem 原生服务只接收既有 IPC 契约的结构化连接配置，不保存账号令牌、不调用本业务 API。本文的服务器 Go API 与本地 Go 网络服务是两个独立程序。

主动登出沿用已有产品流程：有连接时先确认并断开，尽力调用 `/auth/logout`，然后清除本账号本地会话与缓存。若撤销请求失败，应说明仅完成本地退出，不能声称服务端已经撤销。网络错误、429、503 和访问令牌到期不能直接清除会话。认证状态与现有代理连接状态分开管理，继续遵循 [D-15](../adr/0015-cache-until-known-expiry.md) 的已知有效期规则。

## 4. 节点列表、详情与统一模型

### 4.1 游标分页

按 [D-23](../adr/0023-default-connectable-resource-view.md)，客户端资源选择页默认显示“可连接”，并提供“全部资源”视图。当前 `/nodes` 只能作为前者的数据基础；完整资产接口、筛选与不可连接原因仍需补齐。“可连接”为空不能表示“没有购买”，也不能把当前节点列表当作全部资产。

[D-25](../adr/0025-currently-owned-resources-only.md) 明确“全部资源”只包含当前仍归属用户的资源；到期未回收的仍展示，已回收或转出的不保留历史条目。完整资产接口需要提供可靠的当前归属/回收语义；不能只看历史 `released_at`，也不能将某一页没有记录、筛选无匹配或请求失败视作回收。当前确无资源时显示“暂无资源”。

第一次请求 `/nodes?per_page=100`，不要传 `cursor`。后续原样使用响应的 `next_cursor` 并做 URL 编码；`per_page` 范围 1–100，默认 100。客户端不传 `page`，也不能依赖 `total` 或 `last_page`。

```json
{
  "success": true,
  "data": {
    "items": [
      {
        "id": "456",
        "name": "Hong Kong #456",
        "customer_remark": "办公线路",
        "protocol": "socks5",
        "host": "relay.example.com",
        "port": 10001,
        "username": "EXAMPLE_NODE_USERNAME",
        "password": "EXAMPLE_NODE_PASSWORD",
        "country_code": "HK",
        "country_name": "Hong Kong",
        "city": "Hong Kong",
        "expires_at": "2026-11-10T08:00:00Z",
        "is_forwarded": true
      }
    ],
    "pagination": {
      "per_page": 100,
      "has_more": true,
      "next_cursor": "EXAMPLE_OPAQUE_CURSOR"
    }
  },
  "server_time": "2026-10-11T08:00:00Z"
}
```

以 `has_more` 判断是否结束；短页或空页仍可能有后续页。`has_more: false` 时 `next_cursor` 可以省略。缺少必须字段属于契约异常，不能伪装为合法空列表。分页可取消并按订阅 ID 去重，不提供大 OFFSET 或全局一致的整表快照；其他程序提交的变更可能在后续页体现。某页没出现节点不能直接当作撤销。

连接或切换前请求 `/nodes/{subscriptionId}`，成功的 `data` 直接是上述单个节点对象。使用详情重新取得当前凭据和资格，无需逐页定位。详情 404 为不存在或不属于本人；409 `node_unavailable` 为本人资源当前不能连接，均禁止用旧配置开始新连接。

[D-40](../adr/0040-recently-connected-first.md) 的最近成功连接排序由客户端处理，当前接口不提供使用历史字段。按显示需要通过订阅 ID 限并发核实最近项，与分页列表按稳定标识去重；原始 `next_cursor` 继续原样使用，不能用界面排序后的最后一行替代。详情错误与缓存不能伪装为当前可连接，完整资产及筛选能力仍须补齐。

### 4.2 字段映射与资格

| API 字段 | 客户端含义与限制 |
| --- | --- |
| `customer.id` | JSON 整数；统一账号模型转为字符串，不与不同环境或数据源混用 |
| 节点 `id` | **订阅 ID 字符串**，不是官网原始 IP 资产 ID；不能按名称或地址猜测迁移映射 |
| `name`、国家和城市字段 | 展示信息，不作为授权条件 |
| `customer_remark` | 独立的客户订阅备注，字符串；无备注时为 `""`。`name` 始终保留资产名称，备注不覆盖它。裸资产无对应订阅时为 `""`；兼容旧服务器时允许字段缺失，按无备注处理 |
| `protocol` | D-24：每个资源唯一的协议字段，不提供协议候选列表；本版只返回 `socks5`，其他协议参数仍待后端契约补齐 |
| `host`、`port` | 中转入口；`host` 不是预期出口 IP，不可用来代替 D-07 出口验证 |
| `username`、`password` | 当前节点认证信息；按连接配置秘密处理，禁止写日志和诊断摘要 |
| `expires_at` | 客户订阅到期时间，UTC 或 `null`；内部保留 UTC 时刻，按 [D-38](../adr/0038-beijing-expiry-display.md) 仅在界面转换为北京时间（UTC+8）；`null` 显示未指定到期，不编造永久有效、时间或 72 小时限制 |
| `is_forwarded` | 本接口成功节点固定为 `true`，服务端已筛选有效中转资源 |

服务端从现有业务表核实账号、归属、订阅有效期与状态、中转资格、IP 状态、历史释放/再次启用关系、当前有效中转规则、设备组及入口。入口按订阅自定义、套餐展示、设备组自定义、设备组原始连接域名的顺序选取；绝不回退到资源的原始静态 IP。客户端仍须校验响应完整性、支持的协议和已知有效期，最终中转认证及撤销执行由中转服务端负责。

本 API 没有返回 `customer.forward_certified`。不能将其缺失补成 `false` 后拒绝所有节点；当前接口以服务端返回的本人合格节点作为逐资源资格证据。此规则不能泛化成让所有静态 IP 获得连接资格。

[D-24](../adr/0024-one-protocol-per-resource.md) 确认不同资源可以使用不同协议，但每个资源只提供一种协议。适配器将该资源的唯一当前配置交给连接层；资源详情仅展示协议，不保存协议偏好，也不构造多协议候选或自动回退。

### 4.3 固定预期出口字段（D-29，待实现）

[D-29](../adr/0029-fixed-expected-exit-ip.md) 要求每个可连接资源提供单值 `expected_exit_ip`；[D-33](../adr/0033-current-ipv4-egress.md) 确认当前类型为 IPv4 字面量字符串，表示该资源固定唯一的公网出口。客户端映射为 `expectedExitIp` 并传入原生 `exitCheck`；经所选资源访问 IPv4 检测目标，实际 IPv4 必须与它一致才放行业务。入口地址族独立于该出口字段。

当前 `/nodes` 和详情响应尚无该字段，上面的 JSON 示例仍表示当前实现。字段缺失/无效时正式客户端不能跳过比对，不能使用 `host`、展示地址或首次探测结果猜测。源表的权威字段及对应关系须由 B-04/S1 核实；不把本次产品语义确认当成字段已交付。

## 5. 错误处理表

| HTTP / code | 客户端处理 |
| --- | --- |
| 401 `invalid_credentials` | 登录账号或密码不正确，留在登录页；不要为登录失败调用自动续期 |
| 401 `unauthorized` | Bearer 缺失或格式不正确；检查请求组装与本地会话，不能无限重试 |
| 401 `invalid_token`、`access_token_expired` | 受保护请求经唯一会话管理器续期，原请求最多重试一次 |
| 401 `credentials_changed`、`account_unavailable`、`session_revoked`、`session_expired`、`invalid_refresh_token`、`refresh_reuse_detected` | 会话终止或无法恢复，要求重新登录；区分提示原因 |
| 403 `account_disabled` | 提示账号停用，不循环刷新令牌 |
| 404 `not_found` | 对节点详情表示不存在或不属于本人；不退出整个账号 |
| 409 `node_unavailable` | 资源暂不可用，更新资源状态，禁止新连接；不退出账号 |
| 409 `stale_refresh`、`refresh_retry_expired` | 按 §3.2 的持久化状态恢复，不能回写旧令牌 |
| 422 `validation_failed` | 检查参数；不把开发错误当作认证失败 |
| 413 `payload_too_large`、405 `method_not_allowed` | 修正请求体或方法 |
| 403 `https_required` | 修正 HTTPS/可信反向代理配置，不降级到公网 HTTP；按 code 与账号停用区分 |
| 429 `rate_limited` | 遵守 `Retry-After`，退避并保留会话 |
| 503 `service_busy`、`service_unavailable` | 排队、过载或依赖故障；遵守 `Retry-After` 并保留会话，续期重试复用原请求标识 |

错误示例：

```json
{
  "success": false,
  "error": {"code": "access_token_expired", "message": "Unauthorized"},
  "server_time": "2026-10-11T08:31:00Z"
}
```

## 6. 与其他程序共用数据库时的约束

这里记录实现边界与默认预算；不能把 Go 的并发能力等同于数据库容量，也不能把测试数据量当作生产容量结论。

2026-10-12 最新生产部署决定为 `127.0.0.1:3306/api_all_sunip_cc`、单账号 `v2_test`：source / sessions 两池使用相同账号密码，账号有库级 SELECT 和三张 API 表的指定写权限；source 池额外开启事务只读，两池连接预算合并计算。部署新建 **3 张表**：`bg_client_sessions`、`bg_client_refresh_tokens`、`bg_client_device_sessions`；由 DBA 按交付 SQL 预建并授权，运行账号不需要 DDL 权限。JSON 键仍是 `source`、`sessions`，Hytron 测试服务仍使用 `suntest`。完整步骤见部署手册。

| 项目 | 已实现措施 / 默认值 |
| --- | --- |
| 业务读取 | 独立 source 连接池；每个新连接启用事务只读与 READ COMMITTED；普通 SELECT，不锁业务行，不写客户、订阅、中转、IP 等源表 |
| 会话写入 | 独立 sessions 连接池；只写 `bg_client_*` InnoDB 表；短事务、行锁保护同设备登录及刷新轮换，死锁等可重试事务错误最多尝试 3 次 |
| 连接预算 | 每池 max_open=16、max_idle=8；单实例合计最多 32 条连接，连接寿命 5 分钟、闲置 1 分钟 |
| 过载保护 | 在途请求最多 128；密码计算并发 8、等待最多 12 秒；请求 15 秒、查询 2 秒、事务 3 秒超时 |
| 限频 | 登录每 IP 每分钟 120；续期每 IP 每分钟 240；读取每会话每分钟 120；账号尝试按客户 ID 合并用户名/手机号，1 分钟窗口最多 5 次，成功校验会清除该计数；登出不受读取限频影响 |
| 密码校验 | 昂贵计算在事务和数据库连接之外执行；成功后重新读取账号身份、状态与密码指纹，避免覆盖其他程序的改密/停用结果 |
| 节点一致性 | 一次 JOIN 读取同一语句的 MVCC 快照，避免同一次节点响应混用其他程序更新前后的凭据；分页查询每次最多读 101 行 |
| 手机号查询 | 目录保存手机号与 ID，默认每 30 秒按主键批次刷新，最多 25 万条；登录仍回查当前手机号、状态和密码，不缓存授权结论 |
| 多实例 | 会话正确性由数据库事务保障；限频与在途控制是每实例预算，不是集群共享限额 |

其他程序未提交的更新不会让本服务读取脏数据；已经提交的变更可被后续查询观察到。普通读取仍消耗 CPU、IO、连接和元数据锁资源，不能宣称对其他程序零影响。生产应统一计算所有实例和其他程序的连接预算，评估查询计划、数据规模、统计信息及主库负载；默认值不是生产推荐容量。

业务授权读取应使用主库或能保证所需一致性的源；异步只读副本的延迟会推迟改密、停用或撤销的生效观察。COMMIT 结果不明时不盲目重复事务，由续期请求标识恢复结果。连接池等待和排队都有超时，返回 503 时客户端应退避，不能无限重试放大流量。

本地迁移文件及测试库显示手机号缺少索引，故当前实现使用目录；**未检查生产库的实际索引**。API 不自动建业务索引、不修改业务表结构、不在业务表运行 ANALYZE。若后续确需索引或统计信息维护，需单独评估并由数据库维护流程执行。

## 7. 运行交接与验证边界

运行配置放在网站公开目录之外，限制文件权限。数据库密码和持久化的 32 字节令牌密钥不写入开发文档或 Git。按最新方案，单账号 `v2_test` 对业务表只有 SELECT，对 API 三张表有指定读写权限；业务连接额外设置事务只读。当前地址为本机回环，可使用 `tls="false"`；若以后改为远程地址，必须验证 TLS，不使用跳过证书验证的配置。测试与生产的库名、会话数据和令牌密钥仍需区分。

首次初始化使用显式 `-migrate`，只创建会话表；正常启动不自动迁移。`-check` 用于检查依赖，`-check -explain-customer <id>` 检查计划，`-prune` 清理过期会话记录；具体完整命令见服务端 README。密钥首次生成后须保留，不能每次重启生成新值。Hytron 测试环境已按用户后续指示完成初始化和服务启用，其他环境不能据此视为已部署。

反向代理必须覆盖设置 `X-Forwarded-Proto` 与 `X-Real-IP`，只信任配置的代理网段；默认只信任回环代理。Hytron 已补齐请求头并通过 HTTPS 验证，配置文件、服务命令和本次操作范围见运行记录。当前仍未连接生产数据库。

2026-10-11 已保存的服务端验证记录包括：

- `go test -race`：91 个测试函数、236 个子测试通过，无竞态报告；`go vet`、Linux 构建通过。
- 100 个不同客户并发登录，bcrypt cost 10、8 个密码工作位、两池各最多 4 个连接，全部成功；普通构建测试约 992 ms，p95 约 906 ms。数据为隔离测试结果，不是生产 SLA。
- 2 万订阅、200 条本人资源，游标分页结果完整且无重复；统计信息仅在生成的测试表维护。验证了业务并发写入、归属变化、改密/停用、连接池超时恢复及并发续期。
- 可达及已导入包漏洞检查为零；依赖中的未导入 OpenPGP 公告及完整说明见验证记录。

上述开发测试不等于真实 Flutter 客户端、Windows/Android 端到端连接或生产负载已经通过验收；后续启动完成的公网健康检查和接口冒烟验证单独记录于运行文档。
