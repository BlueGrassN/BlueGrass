# ADR 0017：Windows 关闭窗口默认隐藏到托盘

- 状态：已接受。
- 决策日期：2026-10-10，Asia/Hong_Kong。
- 对应事项：设计审阅报告 D-17。
- 确认依据：用户选择 A，点击关闭按钮隐藏到托盘并继续连接，托盘菜单提供明确退出入口。

## 决定

1. Windows 点击窗口“×”或触发常规窗口关闭操作时，默认隐藏到系统托盘；不调用断开、解除保护或退出进程的流程。
2. 首次关闭时提示客户端仍在后台运行及退出入口；提示状态按操作系统用户保存，后续关闭不重复打扰。
3. 托盘显示当前连接/暂停/保护状态，提供显示主窗口、连接或断开、全局接管和退出等操作。
4. 用户选择托盘“退出”时执行完整停止流程：取消待处理连接和验证、停止业务、按归属恢复系统代理及本产品网络设置，然后退出界面。清理失败时提示具体残留与恢复入口，不把失败显示为已恢复。
5. 托盘图标点击或再次启动客户端时激活原窗口，遵循单实例规则，不重复建立连接或启动另一套数据面。

## 生命周期边界

- 隐藏窗口不改变已连接、已暂停或保护阻断状态；不会因窗口关闭而自动连接、自动恢复直连或切换资源。
- 到期/撤销后的暂停继续按 D-08 执行；用户选择退出才按主动恢复语义处理。
- 界面异常退出按已有恢复机制处理，不冒充用户主动退出；后台服务与保护意图保持各自生命周期。
- Windows 系统注销、关机和重启使用平台生命周期处理，与保护意图策略一致，不能把系统结束流程当成普通隐藏窗口操作。
- 托盘创建失败时保持主窗口可见并提示，避免隐藏唯一可用控制入口；Explorer/托盘恢复后重新注册图标并同步状态。
- 本项针对 Windows。Android 的界面退后台与 VPN 前台服务沿用其平台设计。

## 验证要求

覆盖连接中、验证中、重连中、已暂停及保护阻断时关闭窗口，确认连接与保护意图不被解除；首次提示仅一次，托盘和再次启动可恢复窗口。验证托盘退出、网络清理失败、其他软件接管代理、托盘不可用及 Explorer 重启等场景。
