# ADR 0024：每个资源只提供一种协议

- 状态：已接受。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：全项目复核 C01/C02；资源、协议及连接配置的对应关系。
- 确认依据：用户明确“每个资源，只会提供一种协议”。

## 决定

1. 每个资源仅提供一种协议，由服务端给出该资源的协议类型与对应参数；客户端读取并使用它。
2. 资源列表每个资源展示一条记录，资源详情只展示该资源的协议，不提供协议选择器，不按协议复制资源条目。
3. D-03 的客户端多协议支持范围保持不变：不同资源可以使用不同协议，并由同一套客户端连接；不要求同一资源同时提供多种协议。
4. 每个可连接资源对应一份当前协议连接配置，模型使用单个 `protocol` 及其认证、传输、安全和能力字段，不增加协议候选数组、协议优先级或逐资源协议偏好。
5. 协议不受支持或参数不完整时，按现有资格规则提示原因并禁止连接；不猜测协议，不切换到另一种协议作为失败回退。
6. D-14 已接受的服务端加密迁移如发生，按同一资源的当前配置更新处理，不转化为用户可选的多协议列表；继续遵循配置更新、资格与出口验证规则，失败不隐式降级。

## 数据与实现边界

- 当前 Go API 的每条节点已经只有一个 `protocol`，但目前只返回 `socks5`；这不表示 D-03 其他协议的字段契约和运行验证已经完成。
- 列表条目以稳定资源身份区分，不因为多个资源使用同一种协议而合并，也不按名称或地址猜测资源对应关系。
- 完整资产身份、配置版本、逐协议参数及 UDP/IPv6 能力仍需按 C01/C02 补齐；本条不增加多个可选入口或自动协议选择功能。

## 验证要求

- 不同资源分别使用不同协议时，各自使用服务端给定的类型和参数，列表没有按协议重复的资源条目。
- 资源详情展示协议信息，没有协议选择控件；连接请求携带该资源唯一的当前协议配置。
- 协议不支持、参数缺失或连接失败时，不尝试其他协议；同资源配置更新仍执行已有资格和出口验证要求。
