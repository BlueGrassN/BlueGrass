# ADR 0033：当前资源统一使用固定 IPv4 出口

- 状态：已接受，字段交付、探测和平台验收待完成。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：C02/C05/C06；细化 D-29 的出口地址族及 B-02/S11/S12 的当前交付范围。
- 确认依据：用户选择 A，当前提供给客户端的资源全部为固定 IPv4 出口。

## 决定

1. 当前资源按 IPv4 公网出口交付。D-29 的 `expected_exit_ip` 是必需的单个 IPv4 字面量字符串，客户端与原生层分别映射为 `expectedExitIp`、`exitCheck.expectedExitIp`。缺失、格式无效或给出 IPv6 值都属于当前配置契约异常（SYNC-003），不得跳过校验。
2. 出口检测经所选资源访问 IPv4 检测目标，保留 HTTPS 的原域名、SNI 和证书验证。自建及备用端点都须具备可验证的 IPv4 探测路径；不能仅限定客户端到本地代理的连接地址族，就假设代理到检测端点也使用 IPv4。具体端点和逐协议控制方式由 S11/S12 验证。
3. 实际探测值必须是有效 IPv4，并按地址值与权威预期值严格比较。IPv4 不匹配或得到有效 IPv6 出口值都按出口不匹配（CONN-005）处理，不放行业务；格式错误或未取得有效 IP 按原探测失败规则处理。检测失败不改用本地直连，也不挑选备用端点的有利结果掩盖有效不匹配。
4. TUN/VPN 继续接管公网 IPv4 和 IPv6；当前公网 IPv6 业务阻断，不本地直连。受控公网业务 AAAA 查询按既有策略返回空答案（NOERROR/NODATA），保留 A 查询；这不保证仅支持 IPv6 的目的地可访问。缓存地址、IPv6 字面量及其他解析路径得到的 IPv6 仍受流量层阻断。
5. D-31/D-32 允许的本地 IPv6、内网 AAAA 与 mDNS 继续按本地路由和接口作用域处理。不得通过关闭整机 IPv6 或一律清空所有 AAAA 来实现公网出口限制。
6. 中转入口与底层网络的地址族独立于公网出口：本决定不将入口 `host` 限制为 IPv4，也不证明入口或 IPv6-only 网络已可用。入口解析、网络绑定和可达性仍按 D-04/B-02/S8/S12 验证。
7. 系统代理模式只约束进入本地代理的业务，当前公网目标采用 IPv4 路径；不能据此承诺未使用代理的应用也无 IPv6 直连。TUN/VPN 的全局保护按各平台门禁验收。

## 能力与接口边界

- 领域模型中的 `capabilities.ipv6` 指公网代理业务的 IPv6 出口能力，不指 LAN 或入口连接能力。当前交付策略为不支持公网 IPv6；应记录这是产品范围限制，不能伪装成当前 API 已返回该能力字段或已实测的结果。
- 当前 Go API 尚未返回 `expected_exit_ip` 和完整能力字段。响应示例保持当前实现；权威出口来源映射仍由 B-04 核实。
- 本决定只确认出口地址族；后续 [D-34](0034-current-resources-tcp-udp.md) 已单独确认当前全部资源支持 TCP 与 UDP，实际配置和运行验收仍待完成。D-03 的客户端多协议支持目标继续保留。
- 未来引入 IPv6/双栈资源时，另行扩展出口字段、探测、DNS 和能力契约并验收；不能只放开阻断规则或把双出口塞进当前单值字段。

## 验证要求

- 首次连接、切换、重连均经所选资源完成 IPv4 探测和固定出口比对；覆盖字段缺失、IPv6 预期值、错误结果、双栈端点、备用失败及迟到响应。
- TUN/VPN 下覆盖公网 AAAA、缓存 IPv6、IPv6 字面量和直接访问；公网 IPv6 不得漏到物理网络。已允许的本地 IPv6、内网 AAAA、作用域与发现流量分别验证。
- 逐协议确认远端目标采用 IPv4，入口与出口地址族分别记录；单次 TCP 出口检测不能证明 UDP、全部协议或平台保护已通过。
- 本次仅记录业务前提与同步设计，没有新增接口字段、修改设备网络或执行运行验证。
