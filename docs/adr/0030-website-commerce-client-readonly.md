# ADR 0030：订阅与续费由官网处理，客户端读取资源状态

- 状态：已接受。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：客户端范围与全项目复核 C01/C03 的资源数据边界。
- 确认依据：用户明确当前不讨论续费业务，订阅均从官网进行，客户端只需读取到期时间等信息。

## 决定

1. 购买、订阅和续费交易由官网处理；本轮客户端不设计下单、扣费、支付、续订操作或官网订阅记录的生成规则。
2. 客户端通过独立 API 读取本人资源、可连接状态、当前连接配置及到期时间，用于展示、选择资源、连接和已确认的到期处理。
3. 官网完成业务操作后，客户端按现有刷新机制读取最新资源状态与到期时间；不跟踪订单进度，不接收支付/续费完成回调，不用网页交易结果直接批准连接。
4. 可以保留“打开官网”的便捷入口；网络保护生效时仍执行已确认的主动恢复规则，不由交易流程自动解除保护。入口不代表在客户端实现官网业务。
5. 官网续费时更新原订阅还是创建新记录，不作为客户端产品选项继续讨论。API 标识和数据映射由接入层依照既有业务实现核实；客户端使用返回的标识，不自行决定后台生命周期或按名称/IP 猜测资源关联。
6. 普通 API 令牌自动续期仍按 D-19 执行；它属于登录会话维护，与付费订阅续费是不同职责。

## 对当前设计的影响

- 页面和任务中的“续费流程”明确收窄为官网入口与读取最新资源数据；客户端重点保持资源展示、连接、出口校验及网络保护。
- C01 继续补齐当前归属资源的只读数据；C03 继续定义 API 返回有效期变化后如何更新原生调度，不设计交易流程。
- 当前接口的 `expires_at` 等字段按已有契约读取；不根据用户点击官网、充值或支付提示推算新到期时间。
- 余额展示保留为后期功能，短信具体参数继续延后；本条不重新引入已经取消的账号专项设计。

## 验证要求

- 客户端资源操作只读取状态与连接配置，不请求下单、扣费或续订接口，不修改官网业务表。
- 源侧到期时间发生变化后，成功刷新采用最新值；失败、缓存和未加载数据不被显示为已完成的新校验。
- 官网入口及返回 App 的刷新不被当作支付成功证明；连接仍使用当前 API 资格及出口验证结果。
- 保留登录令牌自动续期，不因移出交易功能而移除会话维护。
