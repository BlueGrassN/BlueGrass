# ADR 0039：首次无历史选择时预选首条可连接资源

- 状态：已接受，客户端选择状态与分页交互待实现。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：C01/C08；细化 D-23 的首次资源选择与 D-10 的自动连接边界。
- 确认依据：用户选择 B，首次登录且没有历史选择时预选第一条可连接资源，仍需用户点击连接。

## 决定

1. 当前账号及数据源首次登录、没有历史选择、没有本轮手动选择及已有原生会话时，资源加载得到第一条符合 D-23 可连接条件的记录后，将其预选并展示到首页资源卡片；用户可在连接前改选。
2. 首次无历史时，“第一条”按默认可连接列表的稳定返回顺序确定，先完成对应分页和客户端资格过滤，不按探测延迟或响应到达先后抢选。当前 Go API 的列表按订阅 ID 升序返回；该事实不表示完整资产及筛选接口已经交付。有成功连接历史后的默认排序按后续 [D-40](0040-recently-connected-first.md) 执行，不改变本决定的首次预选边界。
3. 空页仍有后续页时按现有分页与限频规则继续查找，找到首条合格记录即可预选，无须拉取完整列表。加载失败、尚未找到或确认无可连接资源时分别展示对应状态，不能预选不可连接条目或伪造资源。
4. 预选只更新界面目标，不发起连接、不申请 VPN/TUN 接管、不修改系统代理或保护意图。用户点击连接后，按 D-05/D-19 刷新详情、按 D-07/D-29/D-33 验证出口，通过后才放行业务。
5. 预选不能写成“上次成功连接”记录，不能因 D-10 自动连接开关开启而触发首次连接。已有会话、历史选择或用户手动选择优先；列表刷新、加载更多、筛选及迟到响应不得反复覆盖当前选择，账号/数据源不同的响应不能串用。
6. 预选目标随后不可用时提示该资源状态，由用户刷新或改选；一次点击连接不能静默改接另一资源。历史资源失效后的处理不套用本次“首次无历史”预选规则。

## 验证要求

- 首次无历史时预选稳定顺序中的首条合格资源，用户点击前没有自动连接或网络接管；自动连接开关开启也不能把预选冒充成功连接历史。
- 覆盖空页有后续、客户端过滤、失败重试、无合格资源、加载更多、用户先行手选、已有原生会话、账号切换及迟到响应。
- 预选后到期或详情刷新失败时不连接其他资源；正常连接仍须通过既有资格与固定出口门槛。
- 本轮仅同步设计，未实现客户端或修改 API 排序。
