# ADR 0035：UDP 检测不作为连接前置门槛

- 状态：已接受，客户端及诊断服务实现待完成。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：细化 D-07/D-34；C05、S11/S12 的连接体验与诊断边界。
- 确认依据：用户选择 A，出口检测通过即可连接，UDP 在“一键诊断”中检查。

## 决定

1. 首次连接、资源切换及断线重连沿用 D-07/D-29/D-33：当前资源资格有效、中转认证与实际访问成功、HTTPS 检测得到的 IPv4 与权威预期值一致后，才进入“已连接”并放行业务。连接流程不额外发起或等待 UDP 诊断探测。
2. 上述门槛通过后，按 D-34 配置转发公网 TCP 和 UDP；不要求用户先运行诊断才能使用 UDP。协议自身必需的 UDP 握手或传输仍属于建连过程，不能因本决定跳过。
3. 用户运行“一键诊断”时，经当前所选资源发出真实 UDP 数据报检测，记录检测时间、资源、连接代次及结果。未测显示“未检测”，不能用 HTTPS 检测成功代替 UDP 通过。
4. 单独的 UDP 超时、目标无响应或转发失败作为诊断结果展示，不因此断开仍正常的 TCP 连接、不自动换资源，也不允许故障 UDP 本地直连兜底。若可靠诊断结果确认实际出口不匹配，仍按 D-07/D-29 停止相应业务并保持已有保护。
5. 诊断不会在未连接或暂停状态下自行建立业务会话、恢复转发或解除保护；检测不可执行时说明原因。取消、切换、重连后的迟到结果不能标记当前连接为通过或触发对新连接的操作。
6. 本决定只取消额外 UDP 探测的连接前置要求。D-34 的逐协议 TCP/UDP 双向转发、固定出口一致性和故障不直连验收仍须完成；实际 UDP 探测服务与契约仍待 S11/S12 落实。

## 验证要求

- 资格、认证、实际访问与固定出口均通过时，UDP 诊断端点不可用不阻止首次连接、切换或重连；确认连接流程没有额外 UDP 诊断请求或等待。
- 已连接后可直接使用代理 UDP；一键诊断实际执行 UDP 检测，未检测、失败及通过正确区分，普通 UDP 失败不误断正常 TCP。
- 覆盖诊断出口不匹配、取消、断开、切换和迟到响应；原出口门槛及保护规则不被诊断流程绕过。
- 本轮仅记录设计，未新增客户端代码、探测服务或运行测试结果。
