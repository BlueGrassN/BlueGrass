# ADR 0015：缓存以已知有效期为限，最终授权由服务端执行

- 状态：已接受。
- 决策日期：2026-10-10，Asia/Hong_Kong。
- 对应事项：设计审阅报告 D-15。
- 确认依据：用户选择 B，并说明“不靠客户端来阻止连接”。

## 决定

1. 取消 72 小时“未复核”上限，不设置其他由客户端自行增加的失联授权期限。
2. 网页暂时不可用或会话失效时，已有逻辑会话可使用最近已验证的配置继续运行或自动重连，缓存使用上限仅为已知有效期 `validUntil`。
3. `lastVerifiedAt` 用于展示数据新旧和诊断，不单独触发暂停；超过 72 小时未复核也不额外断开仍在已知有效期内的会话。
4. 中转服务端负责最终认证、授权以及到期/停用/撤销执行。客户端判断用于状态展示和已确认的产品流程，不能替代服务端控制，也不能被作为防止绕过购买限制的安全边界。
5. B-01 仍须验证服务端实际行为和生效时延；验证尚未完成不构成恢复客户端 72 小时限制的理由。

## 与已确认规则的关系

- 本次采用的是 B 的“仅以已知有效期为上限”，保留 D-08 的已知到期或明确撤销后的暂停与恢复行为；不自行延长服务端已给出的有效期。
- D-05 的新建会话或资源切换仍刷新资格与配置；缓存恢复仅限原有逻辑会话和同一资源。
- 认证拒绝、明确停用/撤销或到达已知有效期时停止相应业务，保持已有保护并准确显示原因。
- 重连仍执行 D-07 的出口验证；DNS、协议或资源身份异常不能通过使用缓存绕过。
- Windows 和 Android 的正常运行、网络切换、界面重启与系统拉起均采用同一缓存期限策略。

## 有效期与时间依据

- 界面和原生层使用同一份 UTC 有效期及服务器时间校正信息，避免关闭界面后原生层采用不同的到期判断。
- 只有新取得的有效资源状态才能更新有效期和最后复核时间；失败响应和旧缓存读取不刷新这些值。
- 有效期更新须匹配当前资源与会话，再同步至原生层重新安排到期处理；迟到更新不能覆盖其他会话。
- 无法取得新的服务器时间时沿用现有时间策略并注明状态，不凭空增加离线截止时间。

## 验证要求

覆盖网页不可用超过 72 小时但订阅仍有效、同一资源自动重连、应用/系统重启、续费更新有效期、已知到期、明确撤销和服务端认证拒绝。确认客户端不会因缓存年龄单独断开连接，且服务端权限控制独立验证，不能以客户端测试代替 B-01。
