# ADR 0046：到期前七天、三天、一天及到期时提醒

- 状态：已接受，提醒调度、持久化去重与平台通知待实现。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：C03/C08；A-04/U-07 的到期提醒。
- 确认依据：用户选择 A，到期前 7 天、3 天、1 天及到期时各提醒一次，保留系统通知与应用内提示。

## 决定

1. 对纳入提醒范围且具有明确有效到期时刻的资源，设四档：到期前 `7×24h`、`3×24h`、`24h` 及到期时。按 UTC 到期时刻和既定校正时间调度，提醒中的绝对时间按 D-38 显示北京时间（UTC+8）。
2. 每条资源在同一到期时刻下，每档系统提醒一次，应用内同步显示当前提醒状态。去重键包含本机用户、环境/数据源/账号、稳定资源标识、规范化后的 UTC 到期时刻及档位，记录持久化，刷新列表、重开窗口或重启不重复触发同一档。
3. 通知使用可幂等关联的本地标识；持久化调度/提交结果与平台状态衔接。平台接受通知不等于用户已读，拒绝通知权限不能记录成已送达；应用内仍展示到期状态，不因无法通知影响连接控制。
4. 首次取得资源、休眠唤醒或恢复运行时，若已跨过多档，只补当前最紧迫的一档，并跳过已错过的更早档位，不连续补发多条。文案使用实际剩余时间及到期时刻，不把不足一天写成整整一天；已到期只给出到期档。
5. 接受 API 给出的新到期时刻后，取消该资源旧时刻的待发任务，按新值计算并去重；迟到的旧任务执行前再次核对当前账号、资源和有效期，不能发送过时提醒。这只是消费资源更新，不推断官网交易结果或设计续费业务。
6. 到期值为 `null` 时显示未指定到期，不安排四档提醒；格式异常按同步错误处理，不生成虚假日期。明确回收/转出或退出账号后取消相应待发任务，分页缺席或单次同步失败不作为回收证据；使用缓存提醒时标明数据来源/同步状态。
7. 提醒与到期停用分别执行：权限拒绝、系统后台限制、提示关闭或通知延迟，都不能延长 `validUntil` 或阻止原生层按 D-08/D-15 暂停。客户端未运行或系统限制下的准点送达须经平台验证，恢复时按当前档补偿。

## 提醒范围与交互边界

- 后续 [D-47](0047-expiry-reminders-all-owned-resources.md) 已确认覆盖账号全部当前归属资源，包括近期未使用或不可连接的资源；有效明确到期值才调度，null 不编造。原先仅当前所选/最近连接资源的范围由 D-47 替代，提醒取数不受已加载列表页限制。
- 系统通知与应用内提示说明资源及到期信息；用户点击后查看对应资源。不会自动打开官网、解除保护或发起续费；官网入口继续按 D-30 处理。
- 页面持续展示当前到期状态不算重新发送系统通知；同档去重不意味着隐藏仍然有效的到期信息。
- [D-48](0048-grouped-expiry-notifications.md) 确认同轮多资源提醒合并为一条摘要；每条资源的档位与去重独立，只有摘要实际包含并获平台接受的提醒项才记录系统提交成功。

## 验证要求

- 四个档位按真实 UTC 间隔触发，重复刷新、设备时区变化、进程重启及多处订阅同一状态不会重复提交；北京时间展示一致。
- 覆盖首次发现已临近到期、错过多档、到期时间延长/缩短、等价时间格式、null、格式错误、迟到旧任务及账号切换。
- 覆盖通知权限拒绝/恢复、平台投递失败与后台受限；无通知也按时执行已知到期处理，不用通知状态作为连接授权。
- 本轮仅同步设计，没有向系统注册提醒、发通知或执行客户端测试。
