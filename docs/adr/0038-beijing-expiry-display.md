# ADR 0038：到期时间统一显示北京时间

- 状态：已接受，客户端时间格式化与界面验收待实现。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：C03/C08 的到期时间展示；不替代原生时钟及到期调度契约。
- 确认依据：用户选择 B，到期时间统一显示北京时间（UTC+8）。

## 决定

1. 客户端首页、资源列表/详情以及包含到期时刻的提示和通知，统一按 UTC+8 显示，标注“北京时间（UTC+8）”；列表可在公共说明处统一标注。设备时区或所在地区改变不改变显示时区。
2. 完整到期时刻采用 24 小时制 `YYYY-MM-DD HH:mm:ss`。例如接口值 `2026-12-31T20:30:00Z` 显示为 `2027-01-01 04:30:00（北京时间 UTC+8）`，正确处理跨日、跨月和跨年。
3. 接口、领域模型、缓存与原生 `validUntil` 继续保存 UTC 时刻；仅在显示层转换。不把时间戳本身加八小时后存回，也不从显示字符串、剩余天数或日期末尾反推有效期。
4. 到期判断仍比较原始到期时刻与既定校正时间，保留原有精度；展示格式不延后实际暂停时刻。剩余时长依据时间差计算，不能因设备时区改变而增减。
5. `expires_at: null` 显示“未指定到期”，保留其业务含义；不能显示成永久有效、已到期或同步失败。不带时区、只有日期或无法解析的接口值继续按现有契约报异常，不因为本决定而猜测为北京时间。
6. 本决定只统一到期时间的展示，不更改 API 的 UTC 响应、后台订阅业务、其他日志时间格式或既定提醒档位。系统跳时、休眠和重启后的到期处理仍需单独完成工程验证。

## 验证要求

- 同一 UTC 到期值在不同设备时区及切换时区后均显示相同的北京时间；覆盖跨日/月/年和带偏移的等价时刻。
- `null`、缺失字段、无时区和无效时间分别按契约处理；原始值与 `validUntil` 不因格式化改变，显示精度不改变到期判断。
- 首页、列表、详情及到期通知的值和时区标注一致；本轮仅同步文档，未实现或运行客户端。
