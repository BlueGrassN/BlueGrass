# ADR 0036：普通更新后台下载，由用户确认安装

- 状态：已接受，更新器与平台验收待实现。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：细化 D-13；C07、REL-07 的普通更新交互。
- 确认依据：用户选择 B，发现普通新版后自动后台下载安装包，下载完成后由用户确认安装。

## 决定

1. 发现适用于当前平台、架构、系统版本、通道及灰度范围的普通新版后，自动后台下载，无需用户先点击下载。先验证发行清单，再使用其中受信下载地址；不下载不适用的包。
2. 下载期间展示进度，完成完整性与包身份校验后按 [D-44](0044-nonmodal-update-ready-notice.md) 使用应用内横幅/入口角标提示“更新已就绪”，提供安装入口和稍后/收起操作，不主动弹出安装提醒。未下载完整或校验失败的包不能进入可安装状态。
3. 只有用户明确选择安装才进入 D-13 的平台更新流程；后台下载和就绪提示不触发维护暂停、断开连接、服务重启或安装。选择稍后、关闭提示或再次启动客户端都不等于同意安装。
4. 确认安装时说明更新可能短暂中断连接，并取得平台所需授权；保留会话与保护意图，安装后重新核对资格及出口再恢复原资源。下载完成不等于安装成功。
5. 下载中断支持受控重试或续传；断网、空间不足或校验失败只影响本次更新准备，不阻止当前仍受支持版本的正常使用。缓存包与发行版本、平台和校验信息绑定，恢复使用前重新核对，不把旧缓存直接当作可安装包。
6. 本决定针对普通更新。最低支持版本规则按现有设计执行；强制更新与灰度冲突仍按用户先前确认移出范围。

## 网络策略

[D-37](0037-metered-update-download.md) 已确认手机流量或计费网络上等待用户同意，下载中切入该类网络也须暂停未获同意的包下载；恢复符合条件的非计费网络后可继续因网络而暂停的任务。本次允许仅作用于当前更新包，不永久放开后续版本。后台任务的执行、挂起与恢复由平台实现并验证，不据此宣称应用退出后仍能持续下载。

## 验证要求

- 适用的普通新版在下载条件满足时自动进入下载；错平台、错通道、不满足灰度或签名无效时不下载。
- 下载中、下载失败、就绪、选择稍后及客户端重启均不自动安装或进入维护暂停；只有明确安装动作才能进入 D-13 流程。
- 覆盖中断续传、空间不足、缓存包变化与校验失败；正常连接和保护意图保持，安装后的恢复仍重新验证资格与固定出口。
- 本轮只同步设计，没有下载发行包、修改更新器代码或执行安装。
