# ADR 0005：网页取数与 V2 API 适配预留

- 状态：已接受。采用 A：网页按需分页、连接前刷新所选资源，并预留 V2 API 适配。
- 整理日期：2026-10-10，Asia/Hong_Kong。
- 确认依据：用户明确要求保留后续 V2 API 接入，并回复“可以，下一步”，接受调整后的 A 方案。
- 已确认约束：用户当前没有可提供的 API，所有业务数据需要从网页获取；首版不以新增 App API 或单条资源接口为前提。
- 已确认演进方向：后续服务端 V2 会提供 API，首版必须保留接入边界；V2 的具体接口、鉴权和返回结构尚未提供。

## 当前证据

本次只读取了当前客户中心的公开 HTML 和前端脚本，未登录测试账号，也未取得真实资源响应：

- 当前入口脚本 [index-jICEg2N7.js](https://user.sunipip.com/assets/index-jICEg2N7.js) 将“我的 IP”路由指向下述列表模块。
- [列表模块](https://user.sunipip.com/assets/Index-TgY63b21.js) 通过网页内部的 `GET /ips` 请求传入 `page`、`per_page`，并使用 `keyword`、`country`、`product_type`、`expiring_soon`、`sort` 和 `group_id` 等筛选参数。
- [请求模块](https://user.sunipip.com/assets/request-DIHGPNVI.js) 使用基址 `https://api-all.sunip.cc/api/v1/customer`，携带网页登录会话的令牌。
- 未确认按资源 ID 查询单条记录的能力；不能假设存在 `/ips/{id}` 或尚未观察到的筛选参数。

复用网页现有请求仍属于网页数据源适配，不要求后端专门提供 App API。实际登录、响应字段和验证流程仍需在 S1/S2 中验证；只有页面呈现的数据则通过受控网页解析取得。

## V2 API 适配预留（已确认）

业务界面和连接控制只调用统一的 `CustomerDataSource` 接口：首版由 `WebDataSource` 实现，V2 契约发布后增加 `ApiV2DataSource`。两种适配器都输出统一的账号、资源、订阅、中转资格、连接配置和错误模型。

| 统一操作 | 网页适配器 | V2 API 适配器的扩展位置 |
| --- | --- | --- |
| 登录、会话、登出 | 处理现有网页登录、令牌或页面验证 | 按正式契约处理 V2 鉴权和会话，不假设与网页令牌兼容 |
| 资源列表、筛选、分页 | 复用网页请求或解析页面，封装页码与筛选字段 | 将正式分页结果映射到统一列表模型；业务层使用不透明分页标记 |
| 刷新指定资源 | 封装已有详情、筛选或分页定位；向上返回指定资源的最新数据 | 若正式 API 支持单条查询，使用该能力；内部接口不等于承诺后端必须有同名端点 |
| 连接配置与资格 | 映射网页资源、订阅、中转及协议参数 | 映射正式配置与资格字段，继续执行相同的连接和出口约束 |
| 错误与服务端时间 | 将网页异常映射为统一错误和可用时间信息 | 将 V2 错误与时间字段映射到同一模型 |

- 首版定义通用接口、归一化模型、数据源选择入口及契约测试，实际接入网页适配器。V2 的网络实现和字段映射等正式契约提供后再完成，不编造端点或响应结构。
- 网页地址、选择器、原始字段及网页会话逻辑只放在 `data_web`，后续 V2 字段和鉴权逻辑只放在 `data_api_v2`；业务界面不分支处理两套原始数据。
- 数据源由适配器注册和明确的版本/能力配置选择；单条查询、游标分页、令牌刷新和增量同步仅在实际支持时使用。V2 升级可能需要重新登录。
- 切换前验证账号和资源 ID 的对应关系；ID 改变时必须有可靠映射，不能按名称或出口 IP 猜测。缓存与会话按服务环境、数据源版本和账号隔离，旧源的资格结果不能自动成为新源的授权。
- 已有连接绑定其最近验证的资源和配置快照；切换数据源后的新连接重新取数验证。V2 返回 401/403 或明确撤销时，不静默改用网页数据覆盖该结果。
- 迁移前用同一套业务契约测试验证两种适配器；需要回退时，重新验证旧数据源的会话和资源状态。

## 已确认的 A 方案

1. 复用网页登录及现有取数流程，按需加载资源页，使用已验证的网页筛选能力；缓存按账号隔离，未加载的页不伪装成已完成全量同步。
2. 新连接或切换资源前，重新取得账号资格和所选资源的数据。只有经 S1 验证的网页详情或筛选方式能够准确定位资源时，才使用该路径。
3. 没有可靠的单条定位方式时，先刷新该资源上次所在的页面并按稳定资源 ID 匹配；找不到时逐页查找。页号只是查找提示，不能作为资源身份或到期状态的依据。
4. 分页查找限频、可取消，并有总超时；遇到网页验证码或登录失效按正常验证流程处理，不通过未知接口绕过。
5. 抓取失败、列表变化或暂时找不到资源时，显示无法确认，禁止新建会话；已有连接沿用主设计的有效期与撤销规则。不能把某页未出现资源直接视为撤销。
6. 不要求每次打开客户端或点击连接都同步全部资源；定位所选资源时必要的逐页查找可能覆盖全部页。
7. V2 上线后替换或新增数据源适配实现；按需分页和连接前刷新仍是统一业务行为。网页与 V2 的具体查询差异封装在各自适配器中。

## 备选方案：B（未采用）

全量抓取后本地展示适合完整本地搜索、全量统计或批量操作，但增加同步耗时和列表变化处理。当前采用 A；未来出现上述需求时另行评估，连接前重新核实资格的要求继续保留。

## 影响

- B-05 改为验证现有网页的资源定位与刷新流程，不等待后端新增接口。
- 网页数据源适配器负责解析、分页、字段映射及失败分类，业务界面继续使用统一模型。
- V2 接入后保持已确认的按需分页和连接前刷新行为，查询细节由新适配器根据真实能力实现。
- 当前分页与资源定位的具体超时、限频和失败恢复由 S1 验证，不把接口预留当作后端已有能力。
