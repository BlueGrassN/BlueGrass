# ADR 0026：短信登录沿用官网现有短信服务配置

- 状态：已接受，短信接口与客户端待实现。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：全项目复核 C02；D-16 的独立短信登录接入。
- 确认依据：用户选择 A；使用官网现有短信供应商、签名及模板，由独立 Go API 负责发码和校验。

## 决定

1. 客户端短信登录沿用官网现有短信供应商及已配置的短信签名、模板，不另选一套供应商作为首版前提。
2. 客户端请求独立 Go API，由 Go API 调用短信服务完成发送、处理验证码校验，并在成功后签发 D-19 的独立客户端会话。
3. 复用短信服务配置不等于复用官网登录接口、网站令牌或网站验证码校验链路。客户端登录验证码的用途、状态和消费由独立 API 管理，不与官网其他用途的验证码混用。
4. 短信校验成功后仍使用现有长期会话与设备模型：短期访问令牌、滑动刷新和客户端会话独立保存。发送成功不表示登录成功。
5. 供应商凭据只在服务端私有配置中使用，不进入客户端、仓库、日志或诊断报告。签名、模板标识和变量映射按实际配置核实；本决定不记录任何真实密钥。
6. 官网与客户端共同使用同一短信服务配置时，需在接入中核对供应商额度及发送限制；客户端接口的限流和错误处理另形成明确契约。

## 尚需完成的契约

- 核对实际供应商、配置来源、签名和模板变量及适用范围，保存脱敏的接口依据与测试样本。本次选项确认不等于已取得或验证这些配置。
- 定义独立发码/登录请求响应、手机号格式、发送状态、超时及重复请求处理；端点尚未实现，不从官网旧路径猜测。
- 明确验证码有效期、重发间隔、发送数量、校验次数、失效与一次性消费规则；[D-27](0027-sms-limits-without-captcha.md) 已确认不使用人机验证，不再设计验证票据。
- 明确发送/校验的限频与供应商故障映射；按 D-16 验证 Windows、Android 及保护状态下的完整流程。

## 验证要求

- 使用已核实的供应商配置和模板完成独立 API 发码与短信登录，成功后获得客户端会话。
- 官网和客户端并发使用短信服务时，不互相消费验证码或覆盖登录状态；供应商限额和独立接口限频行为可诊断。
- 正确处理发送失败/超时、重复请求、验证码错误/过期/重复使用和限频；不把供应商受理当作登录完成。
- 密钥和短信验证码不进入客户端持久化偏好、日志、诊断及崩溃上报。
