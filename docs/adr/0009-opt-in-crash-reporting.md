# ADR 0009：自建崩溃上报，默认关闭

- 状态：已接受。
- 决策日期：2026-10-10，Asia/Hong_Kong。
- 对应事项：设计审阅报告 D-09。
- 确认依据：用户选择 B，自建崩溃上报由用户主动开启，首版不收集使用行为。

## 决定

1. 首版提供自建崩溃报告接收服务，默认关闭上报。用户在设置中主动开启，并可随时关闭。
2. 上报内容限定为崩溃摘要：应用和内核版本、平台与系统版本、崩溃模块、错误码、脱敏后的符号调用栈及报告时间。按字段白名单生成报告，不直接上传原始异常对象。
3. 不采集页面浏览、点击、连接次数、使用时长、访问域名等使用行为，不为统计建立持久设备标识。
4. 不附带账号令牌、密码、代理凭据、订阅链接、完整代理配置、资源身份或用户访问记录。完整日志和内存转储不进入自动上报；诊断包继续由用户预览后手动导出。
5. 报告仅发送到已配置的自建 HTTPS 接收端，不接入第三方崩溃或行为统计 SaaS。接收服务独立于业务鉴权，不携带网页登录或 V2 业务令牌。

## 开关与发送生命周期

- 未开启时不建立自动上报队列、不请求上报端点；现有本地脱敏日志仍按诊断规则保存。
- 仅在用户已开启时为新发生的崩溃生成待发摘要。崩溃时不能发送的，在应用下次启动后检查设置再发送；不开启后追溯上传先前关闭期间的崩溃数据。
- 关闭后停止后续上报、尽力取消在途请求并删除待发报告。已完成的发送不能通过本地开关撤回，接收端按发布时明确的保留期限清理。
- 待发摘要脱敏后保存，队列、报告大小和重试均有上限；上报失败不影响连接、断线保护或退出恢复，也不触发额外登录。
- 原生进程只向本地受控诊断通道提供脱敏摘要，用户会话中的上传组件检查开关后发送；后台服务不因此持有业务令牌。
- 远程配置只能更新受信接收地址、版本和限频参数，不能打开本地开关或扩展收集字段。

## 服务与验证

自建接收服务纳入首版发布任务，与客户端同时验证 HTTPS、接收格式、大小限制、幂等、限频、访问控制和保留期限；不等待服务端 V2 API 上线。上传使用受约束的控制面路径，不为普通应用开放额外直连权限。

验收覆盖默认关闭零上报请求、主动开启后的新崩溃发送、关闭与队列清理、重启后设置保持、离线重试上限、服务不可达、脱敏扫描以及用户界面和原生进程的崩溃。测试报告不得包含预设的假秘密或使用行为事件。
