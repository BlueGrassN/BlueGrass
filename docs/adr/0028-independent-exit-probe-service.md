# ADR 0028：出口 IP 检测采用独立轻量服务

- 状态：已接受，服务与客户端探测待实现和验证。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：全项目复核 C05；B-10、S11 的出口检测服务。
- 确认依据：用户选择 A；出口 IP 检测与业务 API 分开部署，不依赖业务数据库，业务 API 重启或数据库故障不直接中断检测。

## 决定

1. 自建出口检测作为独立轻量 HTTPS 服务部署，拥有独立的进程、启动与升级生命周期，不合并到 `client-api` 业务 API 进程。
2. 检测服务不查询账号、资源或客户端会话数据库，也不以业务 API 可用作为启动或响应条件；业务 API 重启、升级和数据库故障不直接阻止检测服务处理请求。
3. 服务观察检测请求的来源 IP，并按后续锁定的响应契约返回。原生层通过受控探测通道、明确经当前所选资源访问它；不能借控制面直连路径得到本地物理网络的地址。
4. 检测请求不携带业务访问/刷新令牌、节点认证信息或订阅链接。探测服务的访问限制、可信代理链及来源 IP 获取方式由独立服务契约定义，不借用客户登录和数据库鉴权。
5. 保留既有自建主端点与两个第三方备用端点的方向，端点列表由受信配置管理。主服务失败时按既定探测顺序和时间预算尝试备用端点。
6. D-07 的放行门槛继续执行：验证通过后才开放普通业务；全部端点失败时保持相应保护并允许重试。[D-29](0029-fixed-expected-exit-ip.md) 已确定每个资源的固定预期出口必须与实际结果比对一致。

## 部署与契约边界

- 独立进程和部署是已确认范围；具体域名、路径、部署位置、实例数量及主备故障域仍需落实。不能仅因域名不同就宣称已经具备跨主机或跨机房容灾。
- B-10/S11 锁定 HTTP/响应格式、有效 IP 判定、可信反向代理来源、IPv4/IPv6 行为、错误和限流、无效响应/重定向处理，以及第三方响应适配。
- 检测结果必须属于当前资源及连接尝试；资源变化、取消、过期和迟到结果的放行约束沿用已有设计。
- 业务 API 在故障期间可能无法批准新连接，独立检测不绕过连接前资源复核。两项依赖分别验证，不把探测服务可用误表述为整个连接流程必然可用。
- 本次仅确认架构，没有选择或配置真实域名、部署服务或调用检测端点。

## 验证要求

- 在受控环境单独停止/重启业务 API 或使业务数据库不可用，检测服务仍能正常响应；证据只证明检测服务的独立性。
- 经所选中转发出的探测返回该线路实际出口，不能错误使用控制面直连出口；请求不泄露账号或节点凭据。
- 主端点失败时可使用合格备用结果；全部失败、响应无效或可靠预期不匹配时，业务放行行为符合 D-07。
- 验证取消、资源切换、已知到期和迟到响应，旧探测结果不得放行新的连接。
