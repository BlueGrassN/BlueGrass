# ADR 0025：全部资源仅展示当前归属用户的资源

- 状态：已接受，完整资产接口与客户端待实现。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：全项目复核 C01；补充 D-23 的完整资源展示范围。
- 确认依据：用户选择 A；到期但尚未回收的资源仍展示，已回收、不再归属用户的资源从列表移除。

## 决定

1. “全部资源”指当前仍归属该用户的全部资源，不包含已经回收或转出归属的历史资源记录。
2. 到期但尚未回收、仍归属用户的资源继续展示，标明实际到期状态和适用操作；到期本身不等于回收。仅静态 IP、开通中等仍归属用户的资源也在此视图中展示。
3. 服务端明确确认资源已回收或不再归属本人后，将其从资源列表与可选项移除，不保留“已回收”历史条目。不得继续使用该资源的旧配置批准连接或自动重连。
4. 如果该资源是当前活动资源，仍执行已有的资源不可用/撤销暂停规则并保留必要保护；列表移除不等同于用户主动断开，也不自动改选其他资源。
5. 普通分页中未出现记录、筛选无匹配、请求失败或尚未加载的页面，不构成已回收或归属变化的证明。API 只返回通用不可用结果时，也不能编造具体回收原因。
6. 当前归属资源确实为空时，提示“暂无资源”；不能将这一结果表述成用户历史上从未购买。无可连接资源但仍有其他当前资源时，继续按 D-23 引导查看“全部资源”。

## 数据契约与实现边界

- 完整资产接口必须按当前归属范围返回资源，区分仍持有但已到期与已经回收；当前 `/nodes` 仅包含合格节点，不能代替此接口。
- 当前归属、回收及再次启用以权威业务状态为依据。已有来源可能保留历史 `released_at`，不能只凭该字段非空就排除已重新生效的本人资源；具体字段映射随完整资产契约确认。
- 缓存和刷新按账号隔离；已明确失去归属的资源不能因旧分页响应或旧缓存重新进入可连接候选。分页合并、响应顺序及删除证据继续在资源同步契约中落实。
- 本条只确定客户端列表范围，不删除服务端历史订单、订阅或审计记录，也不新增历史资产归档页面。

## 验证要求

- 到期未回收的本人资源在“全部资源”中可见，已回收或转出的资源不可见。
- 本人当前持有的资源、其他用户资源及历史已回收记录同时存在时，列表范围正确；当前无资源时文案不误报历史未购买。
- 旧释放标记之后重新生效的本人资源按当前权威状态展示，不被历史标记误删。
- 空分页、过滤、同步失败或未加载页不触发误移除；已确认归属变化后，旧响应和旧缓存不能恢复连接资格。
- 活动资源被回收时，暂停及保护行为符合既有设计，不因列表移除恢复直连或切换到其他资源。
