# ADR 0016：密码登录与可选短信登录

- 状态：登录通过 [D-19](0019-independent-client-api.md) 的独立 Go API；2026-10-19 按用户要求明确短信为可选能力，不作为本轮四端 Xray 迁移门槛。未实现或未验证的短信能力不得显示为可用。
- 决策日期：2026-10-10，Asia/Hong_Kong。
- 对应事项：设计审阅报告 D-16。
- 确认依据：用户选择 A，首版提供密码登录和短信验证码登录。

## 决定

1. 四端必须实现账号密码登录和长期会话；短信验证码登录为可选能力。启用短信时，发送与验证码校验须形成完整流程；按 [D-27](0027-sms-limits-without-captcha.md) 不使用人机验证，采用发送频率、数量和错误次数限制。
2. 按 D-19 通过 `ApiV2DataSource` 对接独立客户端 API，官网与客户端登录会话分离。密码登录使用 `/api/client/v1/auth/login`，长期会话通过 `/auth/refresh` 续期；[D-26](0026-reuse-existing-sms-provider.md) 已确定短信沿用官网现有供应商、签名和模板，由独立 Go API 发码和校验。短信接口仍未实现，不能复用官网旧登录作为隐式回退。
3. 补齐独立 API 的发送、验证码校验、限频与会话契约；不接入图形/滑块、验证网页或第三方验证票据，不将网页已有能力当作独立 API 已支持。
4. 原 2026-10-10 的“短信必须进入首轮 Beta”要求已由后续用户决定修订。短信未实现时如实提示，不伪造可用入口或借官网旧会话兜底；不影响其他完整产品要求的独立实现和验收。
5. 密码和短信验证码仅用于当前登录流程，不写入日志、崩溃摘要或长期偏好；登录令牌按已有安全存储及数据源隔离规则保存。

## 验证与错误处理

- 短信发送须遵循待补齐的独立 API 发送间隔、验证步骤和服务端限频反馈；界面展示等待时间与结果，避免重复提交，不把发送成功当作登录成功。
- 分别处理密码错误、验证码错误/过期/次数用尽、请求过于频繁、账号受限、网络失败及会话失效；超过限额时等待或重新申请验证码，不弹出人机验证。
- 短信发送和登录请求使用独立 API 控制通道；S2 覆盖 Windows 系统代理、TUN、保护阻断和 Android VPN 下的完整流程。
- 访问令牌到期由客户端唯一会话管理器自动续期；网络错误、限流或临时依赖故障保留会话，只有明确失效或无法恢复时才要求重新登录。并发续期与安全存储规则见[接入开发文档](../development/client-api-integration.md)。
- 保护状态下验证 API 控制通道可达；不能以解除保护或放行整个外部浏览器代替必要的控制面路径设计。
- 登录完成后以实际取得的客户端会话与账号响应确认成功。

## 交付与验收

各交付平台必须完成密码登录、续期、网络中断、重新登录及账号切换的验收。启用可选短信前，另行覆盖发送、正常登录、错误或过期验证码、发送/校验限额，确认不请求人机验证，秘密不进入日志或上报。短信未启用不作为本轮迁移阻断项；当前平台交付状态见[四端手册](../development/four-platform-development.md)。
