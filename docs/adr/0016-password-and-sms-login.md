# ADR 0016：首版同时支持密码与短信登录

- 状态：密码与短信产品目标已接受；登录实施路径于 2026-10-11 由 [D-19](0019-independent-client-api.md) 改为独立 Go API。当前仅服务端密码登录完成，短信及客户端联调未完成。
- 决策日期：2026-10-10，Asia/Hong_Kong。
- 对应事项：设计审阅报告 D-16。
- 确认依据：用户选择 A，首版提供密码登录和短信验证码登录。

## 决定

1. Windows 与安卓首版同时支持账号密码登录和短信验证码登录；短信发送、验证码校验及必要的人机验证均属于完整登录流程。
2. 按 D-19 通过 `ApiV2DataSource` 对接独立客户端 API，官网与客户端登录会话分离。密码登录使用 `/api/client/v1/auth/login`，长期会话通过 `/auth/refresh` 续期；短信契约尚未实现，不能复用官网旧登录作为隐式回退。
3. 短信若需要人机验证，先补齐独立 API 的发送、票据与会话契约，再验证受控内嵌网页及网络出口约束；不猜测端点，不将网页已有能力当作独立 API 已支持。
4. 不沿用“短信流程复杂就自动移出首版”的假设。若验证存在实现障碍，记录具体依赖与工作量并解决，范围变更须另行决定。
5. 密码、验证码和验证票据仅用于当前登录流程，不写入日志、崩溃摘要或长期偏好；登录令牌按已有安全存储及数据源隔离规则保存。

## 验证与错误处理

- 短信发送须遵循待补齐的独立 API 发送间隔、验证步骤和服务端限频反馈；界面展示等待时间与结果，避免重复提交，不把发送成功当作登录成功。
- 分别处理密码错误、验证码错误/过期、请求过于频繁、账号受限、需要继续验证、网络失败及会话失效。
- 验证票据与登录请求必须满足实际验证服务的会话和网络出口约束；S2 覆盖 Windows 系统代理、TUN、保护阻断和 Android VPN 下的完整流程。
- 访问令牌到期由客户端唯一会话管理器自动续期；网络错误、限流或临时依赖故障保留会话，只有明确失效或无法恢复时才要求重新登录。并发续期与安全存储规则见[接入开发文档](../development/client-api-integration.md)。
- 若保护状态下无法完成网页验证，明确提示用户主动恢复网络后继续；不自动解除保护或为整个外部浏览器增加直连豁免。
- 页面跳转和票据交接限定在经核实的登录/验证流程，登录完成后以实际取得的会话与账号响应确认成功。

## 交付与验收

首轮对外 Beta 前，两种登录方式均须在 Windows 和安卓完成端到端验收。覆盖发送短信、人机验证、正常登录、错误或过期验证码、限频、网络中断、重新登录及账号切换；确认输入秘密不进入日志和上报。内部 Alpha 可以分阶段集成，不能将仅密码登录完成视为首轮 Beta 的登录门槛已达成。
