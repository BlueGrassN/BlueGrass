# ADR 0032：明确的内网域名使用本地解析

- 状态：已接受，原生 DNS 分流与平台验证待完成。
- 决策日期：2026-10-11，Asia/Hong_Kong。
- 对应事项：全项目复核 C06、旧 F05；补充 D-31 的本地域名访问。
- 确认依据：用户选择 A；明确的内网域名使用本地 DNS，公网域名继续采用代理 DNS 策略。

## 决定

1. `allowLan=true` 时支持明确的内网域名解析，由受控原生 DNS 层选择相应网络的本地解析路径；不把全部业务 DNS 回退到系统 DNS。
2. 内网域名在合成 FakeIP 或交给中转远端解析之前分类，成功时使用实际本地解析结果。公网域名继续按现有代理 DNS/域名透传流程处理。
3. 本地解析超时、没有可用本地解析器或网络丢失时，明确返回失败，不改用公共 DNS 或所选中转解析该内网名称。公网解析失败也不回退到本地 DNS。
4. 本地 DNS 策略独立于 D-04 的入口 DNS；用户指定入口 DNS 不会把公网业务查询改成本地解析，也不将公共入口 DNS 列表当作内网域名解析器。
5. 关闭 LAN 访问时停止普通内网域名的本地查询和访问例外，不将这些名称转交公网。必要的 `localhost`/回环及受约束入口解析保留原有语义。

## 名称识别范围

| 名称 | 解析路径与边界 |
| --- | --- |
| `localhost` 及其子域 | 按本机回环语义处理，不发往网络解析器。 |
| `local` 及其子域，例如 `printer.local` | 使用对应链路的 mDNS，保留接口作用域，不交给普通公共递归 DNS。 |
| `home.arpa` 及其子域 | 使用当前网络的本地解析器，不直接转交公网兜底。该名称用于家庭网络，本地服务通过它命名。[RFC 8375](https://www.rfc-editor.org/rfc/rfc8375.html) |
| `lan` 及其子域，例如 `nas.lan` | 作为本产品兼容约定使用本地 DNS；不将 `.lan` 宣称为 RFC/IANA 已注册的特殊用途域。 |
| 其他明确的内网 DNS 路由域 | 仅在具备可核实的网络/管理员域名与解析器映射时纳入；通用搜索后缀、解析失败或返回私有 IP 本身不作为自动扩大本地域范围的依据。额外配置接口与平台来源由 S7/S9 锁定。 |

名称比较按 DNS 标签边界执行，统一大小写并规范末尾根点；`NAS.LAN.` 匹配 `lan`，`nas.lan.example.com`、`evilhome.arpa` 不匹配相应内网后缀。禁止空后缀、根域或全域通配造成所有域名走本地。系统对短主机名的搜索域扩展，应以明确的完整名称/路由域处理，不通过公网解析失败来猜测内网名称。

`.local` 使用 mDNS 的依据为 [RFC 6762](https://www.rfc-editor.org/rfc/rfc6762.html)；`localhost`、`local`、`home.arpa` 的登记见 [IANA 特殊用途域名表](https://www.iana.org/assignments/special-use-domain-names/special-use-domain-names.xhtml)。本表不是将该注册表中的所有特殊名称都送本地 DNS。

## 本地解析器与网络归属

- 从当前底层网络取得实际 DNS 配置，排除本产品虚拟 DNS 地址和指向自身 TUN 的路径；解析器必须与明确的本地网络或 DNS 路由域关联。
- 自动采用的本地解析器须具备可确认的本地可达路径；不能把任意公共递归 DNS 自动视为本地解析服务，也不能猜测默认网关一定在监听 DNS。没有符合条件的解析器时显示本地 DNS 不可用。
- 原生层在正确接口/底层网络上发出解析请求。Android 使用受保护并绑定网络的连接；Windows 保护规则只放行受控原生组件访问当前允许的本地解析器地址、端口和传输协议，不为任意应用开放 LAN DNS 直连。
- TCP/UDP 53 业务查询先进入 DNS 分类器；依据查询名称而非原始 DNS 目标地址决定本地/公网路径。普通应用向路由器查询公网名称，也不能利用 LAN 例外绕过代理 DNS。
- 多网卡、网络切换和同名内网域必须保持网络归属。缓存按网络代次、解析器、域名、查询类型及策略隔离，遵守 TTL；网络或策略改变时清理受影响的本地缓存，迟到结果不能污染新网络。
- 本地名称不合成公网业务使用的 FakeIP。本地 A/AAAA 结果继续按 D-31 的真实地址/本地路由规则处理；名称匹配只决定解析路径，不自动赋予任意公网地址直连权限，也不允许访问本产品虚地址池。

## 查询类型、失败与运行边界

- 本地域名的 A/AAAA、SRV、TXT 等查询使用同一本地策略，不因查询类型改变而走公网；`.local` 继续遵循 mDNS。
- 需要客户端追加查询的 CNAME/SRV 等引用名称重新进行分类，不继承原名称的直连豁免；由本地递归服务器内部完成的解析行为须在其管理域内另行配置，客户端不声称能够控制它的上游行为。
- 私有/本地地址的反向查询按地址用途及本地网络归属处理；RFC 6762 指定的链路本地反向域使用 mDNS，FakeIP 反向信息留在本产品内部，不把整个 `in-addr.arpa` / `ip6.arpa` 当成本地域。
- 真实的名称不存在保留 NXDOMAIN，超时/无可用解析器等报告解析失败；不把失败伪装成解析成功或自动更换为公共 DNS。
- TUN/VPN 下执行完整分流；系统代理模式中，传入本地代理入口的内网主机名同样先分类解析，而不使用代理的应用仍属于系统代理已声明的控制边界。
- LAN 已允许时，中转不可用不应直接阻止符合本规则的本地解析；Android lockdown 和平台发现能力仍须实测，不以关闭系统保护作为实现手段。
- 业务 API/更新域名的控制面 DNS 自举仍属于独立的 F06，不因本地域名功能确认而标记已解决。

## 对现有设计的更新

替代“`.lan` 等后缀首版不做特殊处理”和“本地网络 DNS 只作入口解析候选”的旧文字。D-31 的公网 DNS 不泄漏、FakeIP 优先及本地路由规则继续成立，只增加明确的内网名称查询例外；入口 DNS 自定义范围保持 D-04。

## 验证要求

- `nas.lan`、`printer.local`、`router.home.arpa` 使用正确本地机制，公网名称仍走代理 DNS；大小写、末尾根点及伪装后缀不会误分流。
- 覆盖无本地解析器、只有公共 DNS 配置、NXDOMAIN、超时、中转故障及 LAN 开关；本地/公网两类查询都不互相回退。
- 覆盖 A/AAAA、SRV/TXT、别名引用和本地反向查询；本地结果使用真实地址，不被 FakeIP 或 ULA 优先级错误影响。
- 网络 A/B 使用相同域名但不同结果时，缓存与迟到响应按网络隔离；多网卡与 IPv6 scope 正确。
- Windows WFP 与 Android VPN/lockdown 分别抓包，确认仅受控本地名称查询到达允许的本地解析器，普通应用的公网查询不能借端口 53 直连。
- 本轮仅核对标准与同步设计，未运行解析器、修改 DNS 设置或宣称平台验证通过。
