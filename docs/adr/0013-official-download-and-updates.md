# ADR 0013：官网下载与应用内更新

- 状态：已接受。
- 决策日期：2026-10-10，Asia/Hong_Kong。
- 对应事项：设计审阅报告 D-13。
- 确认依据：用户选择 A，首版通过官网分发 Windows 安装包与 Android APK，并提供应用内更新。

## 决定

1. 官网作为首版统一下载入口，提供签名的 Windows 安装包和 Android APK。首版不增加应用商店发行渠道，后续如需上架再按具体渠道设计和验证。
2. 官网和应用内更新使用同一套已发布的版本清单；按平台、架构、最低系统版本和 stable/beta 通道选择安装包，明确版本与更新说明。
3. Android 沿用按 ABI 分包及通用包方案；Windows 主力版与后续 Win7 版分别提供明确标识的安装包与更新通道。
4. 应用内更新验证签名清单和包完整性，Windows 额外核对安装包发布者；Android 核对包名与应用签名身份，并通过系统安装流程取得所需用户操作。
5. 官网提供已发布版本的校验信息、源码与构建说明入口、帮助文档，以及独立 Windows 网络修复工具。实际下载页路径及托管位置在发布工程中确定。

## 更新与恢复

- 受信下载地址由发行清单提供，支持中断重试或续传；错误平台、架构、版本或签名不匹配的包不得安装。
- [D-36](0036-background-update-download.md) 确认普通新版自动在后台下载，完成校验后提示用户确认安装；下载和就绪提示不暂停连接，不能在选择稍后或客户端重启后自动安装。[D-37](0037-metered-update-download.md) 确认手机流量或计费网络上等待用户同意本次包下载，下载中切网也检查该条件。
- 用户选择安装后进入平台更新流程。升级期间保留逻辑会话和保护意图；Windows 维护状态停止业务转发但维持必要阻断，不能直接采用“断开并删除保护规则”的流程。
- 更新完成后，仅在资格仍有效且出口验证通过时恢复原资源；失败时保留可恢复状态和已有保护，提供修复或按既定方案恢复的入口。
- Android 更新中的 VPN 生命周期按系统实际行为和用户已启用的系统保护验收，不承诺应用进程消失时能单独替代系统保护。
- 自启、自动连接、入口 DNS 和崩溃上报等用户设置在升级后保留，不能因更新自动改变用户选择。
- 回退沿用重新发布上一稳定代码并提高版本号的方案，验证配置兼容性；首版无需依赖 V2 业务 API 获取更新。

## 验证要求

首轮 Beta 前验证官网清单与包的一致性、签名与身份检查、通道和架构匹配、下载中断、覆盖安装及更新失败恢复。覆盖带保护意图更新、更新后重新验证原资源以及用户设置保持。
