# ADR 0010：自启与自动连接默认关闭

- 状态：已接受。
- 决策日期：2026-10-10，Asia/Hong_Kong。
- 对应事项：设计审阅报告 D-10。
- 确认依据：用户选择 A，首次连接成功后询问自启，自动连接由用户自行开启。

## 决定

1. Windows 客户端“登录系统后自动启动”默认关闭。安装时不默认勾选，升级不改变用户已保存的选择。
2. 首次手动连接并通过出口验证后，询问一次是否开启自启。用户拒绝或关闭提示后不重复询问，可随时在设置中修改；已经主动开启时不再提示。
3. “客户端启动后自动连接”是独立开关，默认关闭。仅在用户主动开启后，启动时才尝试连接当前账号与数据源下上次成功连接的资源。
4. 两个开关与提示是否已展示均按操作系统用户保存；开启自启不会顺带开启自动连接。

## 自动连接与已有会话

- 界面启动时先同步原生服务或 VPN 进程状态；已有正常连接只恢复展示，不重复建立连接。
- 没有已有逻辑会话且自动连接关闭时，等待用户手动连接；开启时按 D-05 刷新账号资格和目标资源，按 D-07 验证出口后才放行。
- 没有历史资源、登录失效、资格异常或验证失败时明确显示原因，不选择其他资源代替，不放宽验证。
- [D-39](0039-first-resource-preselection.md) 允许首次无历史选择时在界面预选首条可连接资源，但必须由用户点击连接；预选不等于成功连接历史，也不成为自动连接的替代目标。
- 用户主动断开后，本次运行中不因自动连接开关而立即重新连接；单纯激活窗口或回到前台不作为新建连接的触发器。
- 已有逻辑会话的掉线重连和保护恢复继续遵循原设计及 D-15，不由“启动后自动连接”开关取消。
- [D-45](0045-windows-default-system-proxy.md) 确认 Windows 首次无模式偏好时默认系统代理，后续新会话使用保存的模式；模式选择与自启/自动连接开关独立，已有原生会话和保护意图不被默认值覆盖。

## 平台边界

- Windows 后台保护服务继续按保护意图自动启动和恢复阻断。若客户端界面未自启，服务可保持阻断，等待用户打开客户端继续恢复或主动恢复网络；关闭界面自启不能解除保护。
- Android 的“始终开启 VPN”由用户在系统设置中控制，App 提供引导，不将 Windows 的登录自启开关直接套用到 Android。已有会话的系统拉起遵循补充设计 §9.4，App 新会话自动连接仍默认关闭。
- 自启登记方式和 Android 可用启动路径在平台验证中确定，本决策不承诺未经验证的后台启动能力。

## 验证要求

首次安装两个开关关闭；自启提示只在首次成功连接后出现一次；两项设置独立且升级保持；自动连接仅选择当前账号与数据源的历史资源，并完成资格和出口验证。覆盖已有后台会话、手动断开、窗口激活、登录失效、资源到期，以及关闭界面自启但存在保护意图的重启场景。
