## 并发和规模

| 场景 | 结果 |
| --- | --- |
| 100个不同用户同时登录，bcrypt cost10，8个密码任务，读/写池各最多4 | 100/100成功；普通模式wall992ms，p50 582ms，p95 906ms，max949ms |
| 同样的100用户场景开启竞态检测 | 100/100成功；最终一轮wall11.729s、p95 10.99s；不能将竞态检测耗时当作部署性能 |
| 20个相同refresh并发请求、两个独立Store对象 | 只轮换一次，返回同一结果 |
| 同设备并发登录 | 最终只有一个有效会话 |
| 不同设备/会话 | 不共享会话行锁 |
| 锁等待超时、连接池耗尽、调用取消 | 在期限内返回，连接可恢复，无连接泄漏 |
| 其他连接持有未提交订阅写锁 | 普通读取不阻塞、不读取未提交归属；提交后旧用户失去访问权 |
| 其他连接事务内更新代理账号密码 | 不返回新旧混合凭据，提交后最新值可见 |
| 改密、账号禁用、手机号修改 | 检查当前已提交状态，旧凭据/旧手机号不会继续授权 |
| 2万条订阅、目标用户拥有200条 | 两次游标查询返回200个唯一且属于本人的节点；统计信息更新后普通模式6ms，race模式7ms |

所有结果来自固定测试数据，不是生产容量承诺。实际密码成本、数据库延迟、客户资源分布、索引统计及其他程序负载会改变容量。

## 索引证据

测试基于生产已有的customer_id、subscription_id/status等索引结构。刚批量插入临时表后，旧统计信息使完整JOIN选择较差计划，两页约2.16秒；仅对临时表ANALYZE后，计划变为customer_id/PRIMARY索引合并及ref/eq_ref连接，两页约6毫秒。生产索引和统计信息未修改，生产实际计划也未在线读取。
