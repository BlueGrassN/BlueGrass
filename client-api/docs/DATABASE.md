# 与其他程序共用生产数据库时的边界

## 两个连接池与权限

`source` 仅读官网业务表；每条新 MySQL 连接设置 `transaction_read_only=1` 和 `READ-COMMITTED`。`sessions` 只写独立 `bg_client_sessions`、`bg_client_refresh_tokens`、`bg_client_device_sessions`。两个池可指向不同数据库/账号，禁止把源码读连接借给会话写操作。

默认每个池最多16条连接、8条空闲，生命周期5分钟、空闲回收1分钟。因此单实例合计上限32，不会为每个用户创建连接。实例数量增加时，应计算：

```text
Go实例数 × (source.max_open + sessions.max_open)
+ 官网和其他程序的高峰连接
+ 管理、迁移、故障重连余量
≤ MySQL max_connections
```

Hytron 测试时 max_connections=500，不能据此把 Go 的池也设置成500，更不能推断生产库配置相同。

## 业务一致性与并发写入

业务表不使用 `FOR UPDATE`、表锁或长事务。节点归属、客户启用状态、订阅期限、中转资格、地址和凭据通过同一条 JOIN 获取同一语句的已提交快照。其他程序持有未提交行锁时，普通读取使用 MVCC，不等待该行锁，也不读未提交数据；其他程序提交之后，新请求读取新状态。

密码校验可能很慢，期间不持有数据库连接或事务。校验完成后按客户主键重新读取状态、密码哈希、用户名及手机号，拒绝使用校验期间被另一程序改变的身份信息签发会话。已登录请求仍重新核对客户状态和密码指纹，不缓存账号授权状态。

这不是跨业务库和会话库的分布式事务。其他程序在最后一次读取之后才提交的更改由下一次校验观察到；API 不锁住生产客户行直到 HTTP 响应发完。已建立代理连接的最终到期/撤销执行仍属于代理服务端。

生产权限读取应连接主库或具有相应一致性保证的入口；不能把账号禁用/资源归属检查随意转到有复制延迟的从库。只读连接不等于读取副本。

## 本服务自己的并发写入

- 同一客户、同一 device_id：锁独立设备行，撤销旧会话后签发新会话。其他客户/设备不共享此行锁。
- 续期：固定顺序锁 session 行，再锁 refresh token 行；事务里只访问会话库，不进行密码计算或读取业务库。
- 同 request_id 并发重试返回同一加密收据；不同 request_id 重用旧令牌撤销本设备，撤销必须提交后才返回错误。
- 死锁/锁等待错误仅做最多3次有界重试。COMMIT 网络错误可能已经提交，不能盲目重执行事务；客户端用同 request_id 恢复结果。
- SQL、连接池排队、行锁等待均受 context 截止时间控制。池耗尽时有界等待，超过预算返回可重试503，不销毁会话。

默认业务查询2秒、会话事务3秒、HTTP15秒；最大128个在途请求，8个密码校验任务。超容量返回503/Retry-After；这用于控制过载，不是承诺任何规模都没有请求被拒绝。

## 查询与生产索引

生产实现参照本地 `sunipip-dash`：

| 项目 | 依据与处理 |
| --- | --- |
| 登录 | Customer/AuthController.php:145；username/phone、Hash::check、status=1 |
| 每请求状态 | EnsureCustomer.php:19；启用且未软删除 |
| 用户资源归属 | subscriptions.customer_id，不接受请求覆盖 |
| 中转入口 | ForwardRule.php:125；订阅、套餐、设备组覆盖优先级 |
| 释放后续期 | RouterWifiAccount.php:101；比较 released_at 与 last_renewed_at/started_at |
| 有效期 | 客户订阅 expires_at；供应商 upstream_expires_at 可滞后，不能替代 |
| 老数据凭据 | RouterWifiAccount.php:116；auth字段为NULL时兼容socks5_info |

测试库及本地迁移显示 username 有唯一索引，而 phone 没有索引。生产实际索引尚未在线检查。Go 先使用 username 索引；手机号回退使用按主键分块读取的电话→客户ID内存目录，再按主键读取当前账号，并重新确认手机号仍匹配。

目录仅保存电话与ID，不缓存密码/状态/节点；默认30秒整批替换，最多250000个电话键。失败时保留旧路由信息，且旧电话在业务行更新后立即不能通过重新核对；新电话可能要等下一次目录刷新。容量与周期可配置，启动预热失败时不对外接收请求。更大客户规模应由 DBA 评估 phone 前导索引或 CDC 目录同步；本次不擅自变更共享业务表。

节点采用 subscription.id 游标，单次 SQL 最多101行，不查询全表总数、不使用大 OFFSET、不每节点附加查询。已有 subscriptions(customer_id) 和 forward_rules(subscription_id,status) 是基本支撑；上线前由 DBA 对实际数据分布检查 EXPLAIN、慢查询及是否需要 (customer_id,status,id) 等复合索引。代码不会自动执行这些业务索引 DDL。

可用 `-check -explain-customer <客户ID>` 输出实际节点 SQL 的 `EXPLAIN FORMAT=JSON`，仅查看执行计划，不是 EXPLAIN ANALYZE。批量导入后统计信息可能滞后：本次2万条临时测试订阅在旧统计信息下两页查询约2.16秒，对**临时测试表**执行ANALYZE后相同查询约6毫秒。维护生产统计信息应由DBA根据导入/变更情况决定，API绝不会自行ANALYZE或修改业务表。

不同分页请求各自读取当前已提交状态，不构成跨请求的全量快照。期间其他程序可能新增、删除、转移资源；客户端按ID去重，并在连接前调用详情接口重新确认，不能仅凭一次分页未出现记录就认定撤销。

限流与过载准入当前按 Go 实例计算；会话锁、撤销和轮换保存在 MySQL，可跨进程生效。多实例部署的统一入口限流由部署方管理。运行日志每分钟输出连接池占用和累计等待数，不记录用户凭据或查询内容。

## 验证范围

真实 MySQL 用随机隔离表验证：未提交写锁下读取、提交后归属变更、凭据原子更新、账号停用、手机号变更、历史释放标记、连接池耗尽取消与恢复、并发续期/登录。压力结果明确记录账号数、bcrypt成本、连接池、密码并发和延迟。测试不会访问生产服务器、调用上游或探测节点。
