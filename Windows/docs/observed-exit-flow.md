# 连接后检测并展示出口 IP

状态：用户于 2026-10-12 明确修正，当前 Windows 客户端以本文为准。它替代旧设计中“必须提供固定预期出口、相等才连接”的规则。

## 当前行为

1. 从生产 API 获取本人节点及完整连接参数。保留账号、资源身份、协议参数、入口和已知有效期检查。
2. 用户选择节点后建立本地代理或 TUN 连接。`expected_exit_ip` 缺失、为 null 或与后续观察不同，都不构成拒绝连接的理由。
3. 连接后，经当前所选节点访问 HTTPS 出口检测服务，取得实际出口 IP 并显示在界面。不能通过本机直连检测来冒充节点出口。
4. 检测期间或检测服务失败时，已建立的连接继续可用，IP 显示“暂未获取”；可通过诊断重试。检测结果不决定是否放行业务，也不建立新的预期 IP 绑定。
5. 重连、切换或取消后，旧尝试的迟到结果不得更新当前 IP。显示有效的当前观察；没有观察时不使用节点入口、API 可选预期字段或旧资源结果填充。
6. 到期、用户暂停/断开、实际引擎或网络状态失效仍按现有连接与保护流程处理。第三方检测端点暂时不可用不等于引擎失效。

## 简化范围

- 删除客户端测试出口绑定、绑定构建开关、指定预期 IP 的联调参数和优先选择绑定资源的特殊逻辑。
- 删除领域、控制器、原生引擎及诊断中的预期出口门槛和相等比较。
- API 可选的 `expected_exit_ip` 仅为兼容元数据；不会进入新连接配置，也不会参与节点资格或出口检测。
- 保留私有 IPC 的资源/会话/尝试身份及迟到结果隔离；这些机制用于显示和控制正确的当前连接。

本次不修改 API 服务器，也不要求它补齐预期出口。代码、测试、联调脚本和验证报告均位于 `Windows/`。
