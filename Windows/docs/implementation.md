## 本轮顺序

1. 迁移已有 Flutter 模板至 Windows/app，核实工具链。
2. 实现领域规则、独立 API 会话与分页、原生控制状态机；三者写入不同子目录并行执行。
3. 实现 Windows 界面、当前用户 DPAPI 安全存储、偏好、诊断及托盘。
4. 整合并执行 Dart/Go 回归、Flutter 静态分析、Windows 构建和启动验证。
5. 对候选抽象执行移除前后同一组回归；对安全门禁做负向消融，记录应保留的机制。
6. 独立代码审阅、修复实质问题，记录实际交付及剩余外部依赖。

## 执行决定

- 沿用 feature/windows-client 和当前未提交设计；不重建仓库或替换现有设计。用户指定当前目录，沿用原工作区。
- 本轮目录指令替代旧计划 app/、packages/、native/ 的根级落点，统一迁至 Windows/。
- 当前 API 没有 expected_exit_ip、短信或完整资产接口，客户端不得伪造这些能力；缺固定出口必须拒绝连接。
- 生产入口与显式开发模拟入口分开；测试和 UI 预览不能当作真实网络验收。
- 工具链现场验证：Flutter 3.47.7 (abaf9c5237)、Dart 3.13.5、Go 1.27.2、Visual Studio 2022 17.14.41、Windows SDK 10.0.26100.0。

## 审阅修复

- 本地登出清理失败与仅服务端撤销未确认分别呈现；前者禁止再次登录并提供重试，避免把磁盘上仍存在的会话说成已清除。
- API 确认会话失效/无法恢复续期时清除界面账号及旧列表；暂态错误保留可恢复数据并提供重试入口。
- 偏好损坏不再阻断健康的会话存储；设备记录损坏提供明确确认的本机重置入口。
- 并发偏好写入失败回退到最后成功持久化状态，避免回到同样未保存的中间状态。
- Go 解码器拒绝非 nullable 字段的 JSON null；实际模式只在当前 attempt 准备成功后更新。
- 修复 UTF-8 C++ 编译、宽窗口导航 Material 绘制及字体宽度溢出；覆盖 480/1280 逻辑像素窗口。
