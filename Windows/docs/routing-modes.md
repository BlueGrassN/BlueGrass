# Windows 路由模式与 TUN

## 使用方式

首页的“国内外分流 / 全局代理”决定流量去向；连接按钮旁的“TUN 模式”决定接管方式，两者独立。关闭 TUN 时使用系统代理，开启时使用已有后台服务接管。设置页同步显示这两项偏好。连接或操作进行中须先断开再切换，避免显示状态与运行策略不同。

| 路由模式 | 系统代理 | TUN |
| --- | --- | --- |
| 国内外分流 | 进入本地 HTTP 代理的国内目标直连，其余经所选节点 | 接管业务流量后按同一规则分流，国内直连受精确 WFP 许可约束 |
| 全局代理 | 进入本地 HTTP 代理的公网目标经所选节点 | 公网业务经所选节点；局域网、控制面按已有独立策略处理 |

新安装默认国内外分流和系统代理；老版本已有偏好缺少 `routingMode` 时沿用全局代理。首页的“节点出口 IP”和诊断始终检测所选节点，国内直连流量的出口不用于覆盖该值。本地 HTTP 端口仍为 `127.0.0.1:12808`。

## 规则与 DNS

内置固定 V2Fly geosite、geoip 数据，使用现有 Xray matcher：

1. 明确的国外域名经节点，优先于国内域名和 IP 匹配。
2. 国内域名直连，允许其实际 CDN 使用其他地区的合格公网 IPv4。
3. 其余域名按解析所得 IP 判断：中国大陆 IPv4 直连，其他经节点。字面 IP 使用相同 IP 规则。
4. 分流模式下，国内域名经物理网络向 `223.5.5.5:53/TCP` 解析；其余域名向所选节点后的 `1.1.1.1:53/TCP` 解析。解析一次后连接同一个字面 IP，不允许失败后改用系统 DNS 或直接连接。

TUN 保留 FakeIP，将域名恢复后执行分类；公网 IPv6、私网、CGNAT、虚拟地址池不能进入国内公网直连通道。局域网仍由既有独立开关控制。当前分流不提供自定义规则、按应用分流或数据自动更新，不宣称包含 v2rayN 的所有预设规则。

TUN 分流下，国内域名的 TXT 等非地址查询也使用国内解析器；公网 HTTPS/SVCB/ANY 查询返回成功但无记录，避免地址提示跳过 A/FakeIP 而丢失原域名。客户端随后使用 A 记录连接。局域网解析和全局模式沿用既有规则。

规则版本、来源、校验值、许可证及重建方法见 [routingpolicy](../native/core/routingpolicy/README.md)。软件内嵌的数据不可被工作目录中的文件替换；便携包 `runtime/data/routing-policy/` 中附有同一数据及声明，供审阅和再分发，不作为运行时配置入口。

## 服务边界

`ConnectionProfile.routingMode` 可省略，省略表示 `global`；显式值只能为 `global` 或 `bypass_cn`。它与接管方式 `mode` 独立。API/IPC 不能传入任意路由规则或自行申请 WFP 出口。

国内直连由可信分类代码为当前 TUN 会话申请精确的 TCP/UDP、公网 IPv4、端口许可，仅匹配服务程序。TCP 与 UDP 引用分开计数，最多 256 个活动组合。关闭 socket 归还引用；暂停、重连、退出或恢复清理回收许可。过期会话的回调不能影响新会话。移除失败须记录错误并阻断，不将失败当作清理成功。认证 SOCKS UDP 中继仍使用自己的权限和引用，不混入普通直连规则。

## 验证入口

普通回归入口为 `routingpolicy`、`localengine`、`tunengine`、`winprotect`、`winservice` 包，以及 Flutter 路由偏好和界面测试。`test-elevated-tun.ps1 -PrepareOnly -RoutingMode bypass_cn` 准备管理员验收，随后使用输出目录执行 `-Run`；独立看护进程在任何网络修改前就绪，超时或异常后执行所属网卡/WFP 恢复。实测日志只保存模式、序号、计数、布尔比较和固定错误码，不保存账号、节点或出口地址。

签名服务安装、重启、休眠、多用户与不可用的 IPv6/LAN 基线须分别验证，不能由组件测试代替。
